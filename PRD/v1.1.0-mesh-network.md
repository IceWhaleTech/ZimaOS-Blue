## Overview

ZimaOS Echo 将支持 P2P 分布式网络，允许用户设备之间直接通信，并可选择性地加入中继网络为其他用户提供网络中继服务。该功能参考 [EasyTier](https://github.com/EasyTier/EasyTier) 的设计理念，实现去中心化的网络连接。

## Goals

- [ ] 实现设备间的 P2P 直连通信
- [ ] 支持 NAT 穿透（STUN/TURN）
- [ ] 提供可选的中继节点功能
- [ ] 建立积分激励机制鼓励用户贡献带宽
- [ ] 确保网络安全和隐私保护

## User Stories

### Story 1: P2P 直连

**As a** ZimaOS 用户
**I want to** 直接连接到我的其他设备
**So that** 我可以在不依赖中心服务器的情况下访问我的 NAS

**Acceptance Criteria:**
- [ ] 支持 NAT 穿透自动建立 P2P 连接
- [ ] 连接失败时自动回退到中继模式
- [ ] 显示当前连接类型（直连/中继）

### Story 2: 加入中继网络

**As a** 拥有良好网络条件的用户
**I want to** 将我的设备作为中继节点
**So that** 我可以帮助其他用户并获得积分奖励

**Acceptance Criteria:**
- [ ] 明确的加入/退出中继网络选项
- [ ] 显示资格检测结果（带宽、NAT 类型）
- [ ] 实时显示中继流量和积分收益

### Story 3: 积分激励

**As a** 中继节点运营者
**I want to** 查看我的积分余额和历史
**So that** 我可以了解我的贡献价值

**Acceptance Criteria:**
- [ ] 积分余额实时显示
- [ ] 积分获取/消耗历史记录
- [ ] 积分用途说明（TODO: 定义积分用途）

## Technical Design

### Architecture

```
┌─────────────────────────────────────────────────────────────────┐
│                      Discovery Server                            │
│              (节点发现、NAT 类型检测、中继分配)                    │
└─────────────────────────────────────────────────────────────────┘
                              │
          ┌───────────────────┼───────────────────┐
          │                   │                   │
          ▼                   ▼                   ▼
    ┌──────────┐        ┌──────────┐        ┌──────────┐
    │  Node A  │◀──────▶│  Node B  │◀──────▶│  Node C  │
    │ (Client) │  P2P   │ (Relay)  │  P2P   │ (Client) │
    └──────────┘        └──────────┘        └──────────┘
          │                   ▲                   │
          │                   │                   │
          └───────────────────┴───────────────────┘
                        Relay Fallback
```

### NAT 类型分类

| NAT Type | P2P 可行性 | 可作为中继 | 说明 |
|----------|-----------|-----------|------|
| Full Cone | 高 | ✅ | 最佳，任意外部主机可访问 |
| Restricted Cone | 高 | ✅ | 需要先发起连接 |
| Port Restricted Cone | 中 | ❌ | 需要精确端口匹配 |
| Symmetric | 低 | ❌ | 每次连接端口不同，难以穿透 |

### 中继节点准入条件

```yaml
relay_requirements:
  bandwidth:
    upload_min: 10    # Mbps
    download_min: 10  # Mbps
  nat_type:
    allowed:
      - full_cone
      - restricted_cone
    denied:
      - port_restricted_cone
      - symmetric
  uptime:
    min_hours_per_day: 8  # 建议值
  latency:
    max_to_discovery: 100  # ms
```

### 积分计算公式

```
积分 = 中继流量(GB) × 基础系数 × 质量系数

质量系数 = f(带宽, 延迟, 可用性)
  - 带宽 > 100Mbps: ×1.5
  - 延迟 < 20ms: ×1.2
  - 可用性 > 99.9%: ×1.3
```

### 协议选择

| 协议 | 优点 | 缺点 | 选择 |
|------|------|------|------|
| WireGuard | 高性能、现代加密 | 需要内核支持 | ✅ 首选 |
| QUIC | 用户态、NAT 友好 | 相对较新 | 备选 |
| WebRTC | 浏览器兼容 | 复杂度高 | Web 场景 |

### 参考实现

参考 [EasyTier](https://github.com/EasyTier/EasyTier) 的核心特性：

- 去中心化网络架构
- 多种 NAT 穿透技术
- WireGuard 加密
- 智能路由选择
- 跨平台支持

## API Design

### 节点状态

```go
type NodeStatus struct {
    NodeID      string    `json:"node_id"`
    NATType     string    `json:"nat_type"`      // full_cone, restricted_cone, etc.
    IsRelay     bool      `json:"is_relay"`
    Bandwidth   Bandwidth `json:"bandwidth"`
    Connections []Peer    `json:"connections"`
    Credits     int64     `json:"credits"`
}
```
