## Overview

ZimaOS Echo will support a P2P distributed mesh network that allows direct communication between user devices and optionally enables devices to join a relay network to forward traffic for other users. This feature is inspired by [EasyTier](https://github.com/EasyTier/EasyTier) and aims to provide a decentralized networking layer.

## Goals

- [ ] Enable P2P direct connections between devices  
- [ ] Support NAT traversal (STUN/TURN)  
- [ ] Provide optional relay-node functionality  
- [ ] Build a credit-based incentive system to encourage bandwidth contribution  
- [ ] Ensure network security and privacy

## User Stories

### Story 1: P2P Direct Connection

**As a** ZimaOS user  
**I want to** connect directly to my other devices  
**So that** I can access my NAS without relying on a central server

**Acceptance Criteria:**
- [ ] Automatically establish P2P connections via NAT traversal  
|- [ ] Automatically fall back to relay mode when direct connection fails  
|- [ ] Display current connection type (Direct / Relay)

### Story 2: Join the Relay Network

**As a** user with good network conditions  
**I want to** run my device as a relay node  
**So that** I can help other users and earn credits

**Acceptance Criteria:**
- [ ] Clear options to join/leave the relay network  
- [ ] Show eligibility check results (bandwidth, NAT type)  
- [ ] Show real-time relay traffic and credit earnings

### Story 3: Credit Incentives

**As a** relay node operator  
**I want to** view my credit balance and history  
**So that** I can understand the value of my contribution

**Acceptance Criteria:**
- [ ] Real-time credit balance display  
- [ ] Credit earning/spending history  
- [ ] Explanation of credit usage (TODO: define credit use cases)

## Technical Design

### Architecture

```text
┌─────────────────────────────────────────────────────────────────┐
│                      Discovery Server                            │
│       (Node discovery, NAT type detection, relay assignment)     │
└─────────────────────────────────────────────────────────────────┘
                              │
          ┌───────────────────┼───────────────────┐
          │                   │                   │
          ▼                   ▼                   ▼
    ┌──────────┐        ┌──────────┐        ┌──────────┐
    │  Node A  │◀──────▶│  Node B  │◀──────▶│  Node C  │
    │ (Client) │  P2P   │ (Relay)  │  P2P   │ (Client) │
    └──────────┘        └──────────┘        └──────────┘
          │                   ▲                   │
          │                   │                   │
          └───────────────────┴───────────────────┘
                        Relay Fallback
```

### NAT Type Classification

| NAT Type | P2P Feasibility | Relay Eligible | Notes |
|----------|-----------------|---------------|-------|
| Full Cone | High | ✅ | Best case, any external host can reach it |
| Restricted Cone | High | ✅ | Requires prior outbound traffic |
| Port Restricted Cone | Medium | ❌ | Requires exact port match |
| Symmetric | Low | ❌ | New mapping per connection, hard to punch through |

### Relay Node Admission Criteria

```yaml
relay_requirements:
  bandwidth:
    upload_min: 10    # Mbps
    download_min: 10  # Mbps
  nat_type:
    allowed:
      - full_cone
      - restricted_cone
    denied:
      - port_restricted_cone
      - symmetric
  uptime:
    min_hours_per_day: 8  # Suggested
  latency:
    max_to_discovery: 100  # ms
```

### Credit Formula

```text
Credits = RelayTraffic(GB) × BaseFactor × QualityFactor

QualityFactor = f(bandwidth, latency, availability)
  - Bandwidth > 100 Mbps: ×1.5
  - Latency < 20 ms: ×1.2
  - Availability > 99.9%: ×1.3
```

### Protocol Choices

| Protocol | Pros | Cons | Choice |
|----------|------|------|--------|
| WireGuard | High performance, modern crypto | Requires kernel support | ✅ Primary |
| QUIC | User space, NAT friendly | Relatively new | Backup |
| WebRTC | Browser-friendly | High complexity | For web scenarios |

## API Design

### Node Status

```go
type NodeStatus struct {
    NodeID      string    `json:"node_id"`
    NATType     string    `json:"nat_type"`      // full_cone, restricted_cone, etc.
    IsRelay     bool      `json:"is_relay"`
    Bandwidth   Bandwidth `json:"bandwidth"`
    Connections []Peer    `json:"connections"`
    Credits     int64     `json:"credits"`
}
```
