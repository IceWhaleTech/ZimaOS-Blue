# PRD: Smart Form Filler - Floating Widget for Intelligent Form Completion

**Version**: 0.9.4
**Author**: ZimaOS-Echo Team
**Status**: Draft
**Created**: 2026-01-28

---

## 1. Overview

### 1.1 Background

Users frequently encounter web forms that require repetitive data entry - registration forms, checkout pages, profile settings, etc. While browser autofill handles basic fields, it struggles with:

- Non-standard field names or custom form implementations
- Fields requiring specific formats (dates, phone numbers, IDs)
- Context-aware filling based on form purpose
- Password fields that hide input, making verification difficult

A Smart Form Filler widget will provide an intelligent, floating assistant that can identify form fields through multiple detection methods and fill them accurately.

### 1.2 Goals

1. Provide a floating widget that can be activated on any web page
2. Intelligently detect form fields using multiple strategies (labels, placeholders, patterns)
3. Support format templates and sample-based field recognition
4. Auto-reveal password fields for verification before submission
5. Learn from user corrections to improve accuracy over time

### 1.3 Non-Goals

1. Replacing browser's built-in password manager
2. Storing sensitive credentials (passwords, credit cards) - defer to browser
3. Automated form submission without user confirmation
4. CAPTCHA solving or bot-like behavior

## 2. User Stories

### 2.1 As a User

- I want a floating button that I can click to auto-fill forms
- I want the widget to recognize fields even with non-standard naming
- I want to see what's being filled in password fields before submitting
- I want to provide sample data and have similar fields auto-detected
- I want to correct wrong fills and have the system learn from it

### 2.2 As a Power User

- I want to define custom field patterns for specific websites
- I want to create fill templates for different contexts (work, personal)
- I want keyboard shortcuts to trigger form filling
- I want to export/import my fill configurations

### 2.3 As a Developer

- I want to integrate the form filler with Echo's agent capabilities
- I want to add custom field detection strategies
- I want to access fill history for debugging

### 4.2 Data Models

```typescript
// Field detection result
interface DetectedField {
  element: HTMLElement;
  fieldType: FieldType;
  confidence: number;
  detectionSource: 'attribute' | 'label' | 'pattern' | 'llm';
  suggestedValue?: string;
}

// Fill template
interface FillTemplate {
  id: string;
  name: string;
  isDefault: boolean;
  fields: Record<string, string>;
  createdAt: Date;
  updatedAt: Date;
}

// Site-specific mapping
interface SiteMapping {
  domain: string;
  fieldMappings: Record<string, string>; // selector -> fieldType
  lastUsed: Date;
  userCorrections: number;
}

// Field types
type FieldType =
  | 'firstName' | 'lastName' | 'fullName'
  | 'email' | 'phone' | 'address'
  | 'city' | 'state' | 'zipCode' | 'country'
  | 'username' | 'password' | 'confirmPassword'
  | 'birthDate' | 'company' | 'title'
  | 'custom';
```

### 4.3 Configuration

```yaml
form_filler:
  enabled: true

  widget:
    default_position: "bottom-right"  # top-left, top-right, bottom-left, bottom-right
    keyboard_shortcut: "Ctrl+Shift+F"
    auto_show_on_forms: true

  password:
    auto_reveal: true
    reveal_timeout: 5s  # auto-hide after 5 seconds
    show_indicator: true

  detection:
    use_llm_fallback: true
    confidence_threshold: 0.7
    scan_interval: 1000ms  # for SPA support

  learning:
    enabled: true
    sync_enabled: false
    max_site_mappings: 1000
```

## 6. Security Considerations

- Templates stored locally, never sent to external servers without consent
- Password values are never logged or stored
- Site mappings contain only field types, not actual values
- LLM field classification sends only field metadata, not values
- User can disable learning and sync features
