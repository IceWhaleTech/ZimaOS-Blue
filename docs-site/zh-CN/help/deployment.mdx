# 部署

ZimaOS Blue 的文档站当前按 **Mintlify 托管发布** 的方式准备。

## 仓库里已经具备的内容

- `docs-site/docs.json` 站点配置
- 英文主文档与扩展后的简体中文镜像页
- 本地校验命令 `npm --prefix docs-site run build`
- 文档相关改动的 CI 校验

## 推荐部署方式

Mintlify 当前的标准流程是：

1. 创建或登录 Mintlify workspace
2. 通过 Mintlify GitHub App 连接仓库
3. 把 docs root 指向 `docs-site`
4. 选择发布分支，通常是 `main`
5. 后续再绑定自定义域名

## 为什么仓库里没有单独的部署 Action

这里刻意没有再加一条“静态站点发布”型 GitHub Action，因为 Mintlify 托管流程会在仓库接入后负责同步与发布。

仓库侧主要负责的是校验，而不是直接发布。

## 发布前检查

在 Mintlify 里接入仓库前，建议确认：

- `docs-site/docs.json` 能本地通过校验
- Navbar 里的 GitHub、Releases、DeepWiki 链接正确
- 文档根目录是 `docs-site`
- 默认分支包含最新文档内容

## 本地校验

```bash
npm --prefix docs-site ci
npm --prefix docs-site run build
```

## 日常文档更新建议

当你新增页面、导航或功能说明时：

1. 先跑 `npm --prefix docs-site run build`
2. 确认新页面已经挂进 `docs-site/docs.json`
3. 确认英文与简体中文导航在有镜像时保持一致
4. 再交给 Mintlify 预览或正式发布
