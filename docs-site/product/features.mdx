# Features

![Feature overview](/assets/features.png)

Blue has moved beyond a minimal chat shell. The current product surface spans runtime setup, provider routing, automation, evaluation, extensions, voice, and day-two operations.

## Local-first runtime

- Go-native runtime with low startup and memory overhead
- Desktop, server, NAS, edge, and Raspberry Pi style deployment targets
- Local-first execution model with auditable boundaries
- Preview-aware startup and onboarding flows for first-run or single-user environments

## Interaction surfaces

- Web chat plus dedicated settings, channels, security, audit, automation, billing, tenant, and extension views
- Messaging integrations across more than twenty platforms
- Voice chat with speech-to-text, text-to-speech, session handling, and streaming responses
- Form-filling helpers for browser workflows and repeated data entry
- External agent sessions that let Blue coordinate ACP and A2A style agents beside the main runtime
- One `Research` entry in chat that can auto-route between deep research, bounded analysis, and UI review while keeping distinct final result cards

## Unified research workflows

Blue now treats research as one family instead of three unrelated public entry points.

- `research` is the canonical public entry
- `mode=auto` can choose between `deep_research`, `analyze`, and `ui_review`
- The runtime shares one research-family job model internally
- Final user-facing outputs still remain mode-specific

Read [Research Workflows](/guides/research-workflows) for the routing cues, mode-specific inputs, and public-interface guidance.

## Provider and model control plane

![Provider overview](/assets/providers.png)

- Built-in, platform, custom, trial, and media provider categories in one provider pool
- Custom provider onboarding with base URL, API key, routing priority, API format, and cloud or local location metadata
- Verification, model refresh, pricing review, allowed-model controls, and IDE-assisted discovery
- Default provider selection, drag-sort ordering, failover, health checks, and provider racing
- Model-family routing and fallback patterns that separate product behavior from a single vendor contract

Read [Settings and Provider Pool](/guides/settings-provider-pool) and [Providers and Models](/guides/providers-models) for the operator view.

## Automation, harness, and evolution

- Cron, workflow, webhook, browser-automation, and form-oriented entry points
- Harness run groups for experiments, batches, and reusable evaluations
- Dataset, dataset version, eval spec, baseline, and report management
- Scoring modes for rule, judge, or hybrid evaluation
- Run artifacts, traces, approvals, and evidence-backed reporting
- Evolution workflows for skill revisions, rollback or promote decisions, and self-reflection proposals with patch previews

Read [Automation](/guides/automation) and [Harness and Evolution](/guides/harness-evolution) for the tracked execution workflow.

## Extensions and knowledge surfaces

- Local skill management plus remote skill-store browsing
- Skill source import preview, curated ranking, and search across multiple sources
- Security badges, install-type metadata, artifact classification, and vulnerability signals before install
- Tool catalog surfaces alongside skills so teams can govern reusable capabilities in one place

Read [Extensions](/guides/extensions) for the extension lifecycle.

## Security, governance, and operations

- Sandbox execution
- Prompt injection defense
- Session auditing and audit-log export
- Security scan, threat visibility, blocked IP management, and prompt firewall controls
- Billing summaries for token, cost, latency, and anomaly-style drilldowns
- Tenant and workspace management, user membership, invitations, and limits
- RBAC and WebAuthn support
- Backup, restore, memory, and user-data management inside settings workflows

Read [Admin and Operations](/guides/admin-operations) for the day-two operator story.

## Product philosophy

![Design principles](/assets/design_principle.png)

Blue aims to minimize boilerplate so builders can focus on agent behavior, product shape, and integrations instead of hand-assembling the runtime stack.
