# Features

![Feature overview](/assets/features.png)

Blue is no longer just a chat shell with model wiring. It now reads more clearly as a local-first, evaluatable, evolvable, long-running agent runtime. The matrix below compresses the product surface into the main promises it already makes.

| Capability | What It Delivers |
| --- | --- |
| Harness Runtime, Evaluation, and Evolution Framework | Makes agent evaluation a first-class runtime layer across development, training, and live operation. Blue can run regression and smoke-style checks, score runs, compare against baselines, inspect reports and evidence, and validate runtime behavior. The same Harness evidence path also covers skill evolution, follow-up evaluation, promotion or rollback decisions, and `AGENTS.md` or instruction proposal review. Those proposals can come from the execution loop through Ralph Loop, auto-confirm, and self-reflection. |
| Multimodal Native-Capability-First Runtime | Brings voice, OCR, PDF, browser tasks, document conversion, structured form filling, media processing, and media generation into one native-first execution path. When the job can stay on system and local capabilities, Blue does not needlessly bounce it through an external model, which improves latency, reliability, cost, and always-on agent ergonomics. When needed, it can route by intent into native `t2i`, `t2v`, `i2v`, and `i2i` generation pipelines with no-key fallback, rather than stopping at media understanding. |
| Three-in-One Research Runtime | Exposes one public `research` entry that can auto-route between `deep_research`, `analyze`, and `ui_review`. Underneath, Blue keeps a controllable discovery stack with concurrent providers, caching, deduplication, result fusion, policy-driven fetching, and page reading, then turns that into citation-first research, bounded analysis reports, and structured UI, UX, and accessibility review deliverables. |
| Security and Governance | Blue includes sandbox execution, prompt-injection defense, session auditing, permission control, RBAC, WebAuthn, operational guardrails, and skill security auditing and scanning. |
| LLM Wiki and Knowledge Space | Turns memory, research, and runtime outputs into a wiki-like knowledge surface instead of stopping at recall. The long-term shape includes knowledge compilation, summary pages, indexes, backlinks, freshness, and archive workflows. |
| Skill Store and Marketplace | Provides built-in skill discovery, curation, sync, and local scanning so extensibility exists from day one. |
| Production-Grade Provider Pool | Goes beyond a simple fallback chain. The routing layer already includes a provider pool, health checks, automatic failover, circuit breakers, and provider racing for long-running and production-style workloads. |
| Built-In Local Small Model Runtime | Ships a built-in `Qwen3.5-0.8B + llama.cpp` small-model runtime with auto-download and local acceleration. It can absorb short Q&A, image recognition, tool routing, summarization, context compression, and document pre-processing locally. |
| Long-Running Reliability | Treats OTA updates, backup and restore, config hot reload, and post-failure recovery as built-in operating concerns rather than afterthoughts. |
