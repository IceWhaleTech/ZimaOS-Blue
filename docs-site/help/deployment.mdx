# Deployment

ZimaOS Blue docs are prepared for **Mintlify-managed deployment**.

## What this repository already provides

- Site config in `docs-site/docs.json`
- Curated English canonical pages plus first-batch Simplified Chinese pages
- Local smoke validation via `npm --prefix docs-site run build`
- CI validation on docs-related changes

## Recommended deployment model

Mintlify's current standard flow is:

1. Create or sign in to a Mintlify workspace
2. Connect the GitHub repository through the Mintlify GitHub App
3. Point Mintlify at the docs root directory: `docs-site`
4. Select the publishing branch, typically `main`
5. Optionally bind a custom docs domain later

## Why there is no deploy GitHub Action here

This repo intentionally does **not** add a separate GitHub Actions job to publish static docs artifacts, because Mintlify's hosted flow manages sync and deployment directly after the repository is connected.

The GitHub-side responsibility here is validation, not publishing.

## Pre-deploy checklist

Before connecting the repo in Mintlify, confirm:

- `docs-site/docs.json` validates locally
- The navbar links point to the correct GitHub, Releases, and DeepWiki URLs
- The docs root is `docs-site`
- The default branch contains the latest docs content

## Local validation

```bash
npm --prefix docs-site ci
npm --prefix docs-site run build
```

## Suggested rollout order

- Connect the repo in Mintlify
- Verify the generated preview site
- Add the production docs domain
- Replace repository-relative docs links in `README.md` with the public docs URL once the domain is live
