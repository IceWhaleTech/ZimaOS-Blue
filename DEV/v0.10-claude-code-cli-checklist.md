# v0.10 Claude Code CLI Integration Checklist

[中文版本](../i18n/zh_CN/DEV/v0.10-claude-code-cli-checklist.md)

This checklist tracks the implementation of Claude Code CLI integration as the core LLM backend.

## Goal

Replace direct Anthropic API calls with Claude Code CLI to leverage its context engineering capabilities:
- Automatic file reading and code search
- Tool calling (Bash, Read, Write, Grep, Glob, etc.)
- Session context management
- Automatic summarization and context compression
- MCP (Model Context Protocol) support

## Why Claude Code CLI?

| Feature | Direct API | Claude Code CLI |
|---------|------------|-----------------|
| Context Engineering | Manual | Automatic |
| File Operations | Custom implementation | Built-in tools |
| Code Search | Custom implementation | Built-in Grep/Glob |
| Session Management | Custom implementation | Built-in |
| Context Compression | Manual | Automatic summarization |
| MCP Support | No | Yes |
| Tool Ecosystem | Custom | Rich built-in tools |

## Configuration Example

```yaml
# config.yaml
claudecode:
  enabled: true
  command: "claude"  # or full path: /usr/local/bin/claude
  workspace_dir: "/data/workspace"
  default_model: "opus"
  timeout: 5m
  session_ttl: 24h

  backend:
    args:
      - "-p"
      - "--output-format"
      - "json"
      - "--dangerously-skip-permissions"
    resume_args:
      - "-p"
      - "--output-format"
      - "json"
      - "--dangerously-skip-permissions"
      - "--resume"
      - "{sessionId}"
    model_arg: "--model"
    model_aliases:
      opus: "opus"
      sonnet: "sonnet"
      haiku: "haiku"
    session_arg: "--session-id"
    session_mode: "always"
    system_prompt_arg: "--append-system-prompt"
    system_prompt_mode: "append"
    system_prompt_when: "first"
    serialize: true
```

## Migration Plan

### Phase 1: Parallel Implementation
1. Implement Claude Code provider alongside existing providers
2. Add configuration flag to enable/disable
3. Test with subset of users

### Phase 2: Gradual Rollout
1. Enable by default for new installations
2. Provide migration guide for existing users
3. Monitor performance and errors

### Phase 3: Deprecation
1. Mark direct API providers as deprecated
2. Provide automatic migration tool
3. Remove deprecated code in future version

## Security Considerations

1. **Command Injection**: Validate all arguments before execution
2. **Path Traversal**: Validate workspace directory
3. **Environment Variables**: Clear sensitive env vars before execution
4. **Process Isolation**: Run CLI in sandboxed environment if possible
5. **Session Security**: Encrypt session data at rest
6. **Timeout Enforcement**: Always enforce timeout to prevent hanging
