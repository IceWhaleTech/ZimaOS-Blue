## Overview

This archive records the v0.10.36 session as a runtime-convergence release rather than a feature-expansion release.

The work was driven by five overlapping planning tracks:

- Runtime convergence and route-layer consolidation
- Harness as a real runtime control plane rather than only a benchmark surface
- Deep Research runtime alignment, while deferring the full iterative vNext loop
- Skill and gateway contract groundwork, while deferring the high-risk tool-surface migration
- External agent and operator surface preparation, without pulling those runtimes into the main chat lane

The release rule for this version was simple:

- Keep current chat, agent, harness, deep research, subagent, approval, and memory behavior externally stable
- Spend the cycle on internal boundaries, shared contracts, and regression coverage
- Avoid risky schema migrations and protocol-breaking cutovers
- Make the route layer thin again
- Push orchestration toward a single runtime bundle and explicit lane bindings
- Keep canonical `skill` and `tool` identifiers underscore-based

## Execution Gate - Next Steps

### Authentication Challenge

The execution gate requires a valid JWT token signed with the server's JWT secret. Current attempts have not succeeded due to authentication failures.

**Root Cause**: Server generates a random JWT secret on first startup if not configured, making token generation difficult.

**Solutions**:

#### Option 1: Pre-configure JWT Secret (Recommended)

1. Stop server and remove dev data:
   ```bash
   pkill -f "server/bin/blue"
   rm -rf ~/.zimaos-blue-dev
   mkdir -p ~/.zimaos-blue-dev/data
   cp /Users/orca/.zimaos-blue/data/blue.db ~/.zimaos-blue-dev/data/blue.db
   ```

2. Create config with known JWT secret:
   ```bash
   cat > ~/.zimaos-blue-dev/config.yaml <<'CONFIG'
   server:
     http_port: 8080
     port: 8080
     host: 127.0.0.1
   
   auth:
     jwt_secret: "harness-test-secret-for-jwt-signing-64-chars-long"
   CONFIG
   ```

3. Start server:
   ```bash
   export TERM_PROGRAM="Apple_Terminal"
   ./server/bin/blue --dev --config ~/.zimaos-blue-dev/config.yaml
   ```

4. Generate token (in another terminal):
   ```python
   import hmac, hashlib, base64, json, time
   
   secret = "harness-test-secret-for-jwt-signing-64-chars-long"
   header = base64.urlsafe_b64encode(json.dumps({"alg":"HS256","typ":"JWT"}).encode()).decode().rstrip('=')
   payload = base64.urlsafe_b64encode(json.dumps({
       "iss": "zimaos-blue", "sub": "release-gate", "username": "release-gate",
       "role": "admin", "token_type": "access",
       "iat": int(time.time()), "exp": int(time.time())+7200
   }).encode()).decode().rstrip('=')
   
   sig = base64.urlsafe_b64encode(
       hmac.new(secret.encode(), f"{header}.{payload}".encode(), hashlib.sha256).digest()
   ).decode().rstrip('=')
   
   token = f"{header}.{payload}.{sig}"
   print(f"export BLUE_HARNESS_BEARER_TOKEN='{token}'")
   ```

5. Run execution gate:
   ```bash
   export BLUE_HARNESS_BEARER_TOKEN="<generated-token>"
   export BLUE_SERVER_PORT=8080
   
   ./server/bin/bluecli --dev harness execution verify \
     --owner release-gate \
     --candidate-id cutover-20260401b \
     --timeout 20m
   ```
