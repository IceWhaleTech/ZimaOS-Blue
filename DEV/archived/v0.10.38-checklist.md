## Overview

v0.10.38 is the next archived release after the broader runtime and operator work already captured in v0.10.37.

This version does not try to reopen the main runtime architecture. Instead, it gathers the next dense follow-up wave that landed immediately after that cycle:

- GitHub-backed repository, catalog-source, and tool-registration flows became more complete
- Agentcore Runner settings, context-pack visibility, provider-pool metadata, and runner-facing descriptions received another operator pass
- Skill Store and PluginsView got clearer risk and install-result feedback
- Exec approval surfaces became more legible with command-specific titles and hints
- Legacy management-skill naming was further canonicalized and stale locale routing labels were removed
- A much larger localization/backfill wave landed across built-in skills, built-in tools, harness strings, marketplace tags, GitHub Awesome Skills text, agent deletion copy, and search-result copy
- Companion lifecycle handling, desktop-managed restore behavior, and the web shell all received low-risk reliability and polish follow-ups

The release intent for v0.10.38 is therefore straightforward:

- Keep runtime, REST, SSE, and packaging behavior externally stable
- Fold the post-v0.10.37 feature and polish wave into a single archived release record
- Improve settings, storefront, approval UX, localization, and desktop ergonomics without starting another large migration
- Keep version reporting aligned across server, web, desktop, installer, and test surfaces

## Why This Version Exists

After v0.10.37, the remaining work was less about core runtime shape and more about the product surface around it.

At the start of this window:

- GitHub repository-backed flows still needed a cleaner catalog and registration story
- Agentcore Runner and context-pack work existed, but the settings and operator-readability layer still needed another consolidation pass
- Skill Store risk metadata and install feedback existed, but the visual treatment and result surfacing were still not as clear as they should be
- Approval surfaces still left too much command context implicit
- Legacy management naming and stale locale routing labels still leaked into parts of the product
- The shell and desktop flow still had a few obvious low-risk polish and reliability follow-ups

v0.10.38 exists to close that gap without turning a focused product follow-up into another architecture release.
