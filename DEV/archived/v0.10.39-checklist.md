## Overview

v0.10.39 is the next release record after the broader storefront, approval-clarity, localization, and shell follow-up wave documented in v0.10.38.

This time the center of gravity moves again:

- research-related entry points are being consolidated into one clearer `Research` family
- advisor-style recommendation work can now surface structured candidates, evidence, and second-opinion state instead of collapsing into plain prose
- Blue gains a dedicated knowledge workspace instead of scattering knowledge maintenance behind lower-level flows
- automation grows a more explicit evolution console for skill revisions, evidence, and decision history
- chat recovery becomes more complete by restoring task state and pending interactions during bootstrap
- provider failover, continuation, and acceleration feedback are becoming more explicit inside chat
- native productivity and document flows are moving toward first-class `contacts` / `calendar` / `docx` / `xlsx` / `pptx` / `pdf` surfaces instead of legacy or indirect paths
- execution and sandboxing move toward one Blue-owned surface, with a first-class `blue exec`, tier-aware isolation, and shared runtime defaults for Blue/bluelib-family entrypoints
- local audit, failover, approval, and locale-integrity work continues to reduce operator friction and recovery ambiguity

This document intentionally focuses on the most recent local features and fixes now present in the working tree. Core version/reporting surfaces have been aligned to `0.10.39`, but the emphasis here remains on the user-facing themes rather than an exhaustive listing of every internal refactor.

## Why This Version Exists

After v0.10.38, the next batch of work is less about one isolated page polish pass and more about making several advanced workflows feel first-class:

- research should feel like one coherent capability instead of three partially overlapping entry points
- recommendation/advisor workflows should expose structured decision support rather than forcing users to infer it from long-form text
- knowledge operations need a dedicated home for compiled pages, lint health, and grounded ask-and-archive jobs
- knowledge conflict handling should move beyond detection into one-click repair and progress tracking
- skill evolution and review need a clearer operator surface with revisions, proposals, evidence, and rollback/promote paths
- active chats should recover more context when users return to them
- experimental runner selection and task feedback should feel clearer inside chat instead of surfacing raw refs or vague failure text
- failover and provider acceleration behavior should be visible without forcing users to parse low-level retry mechanics
- productivity and document tasks should prefer honest native-first surfaces over older indirect `office`-style guidance
- execution should have one Blue-owned entrypoint while sandbox policy stays tier-aware and runtime-configurable across product entrypoints
- supporting infrastructure should keep removing friction in approval handling, failover management, session auditing, and locale integrity

v0.10.39 exists to capture that shift in a readable release record.

## Release Summary

v0.10.39 should be read as the next candidate release record after v0.10.38, with the emphasis shifting toward workflow consolidation and operator recovery.

The main themes in this window are:

- a unified `Research` family that keeps mode-specific output while simplifying discovery
- advisor-style recommendation workflows with structured cards, evidence, and harness coverage
- a new `Knowledge` workspace for compiled pages, lint health, ask-and-archive jobs, and in-place conflict repair
- a new `Evolution` console plus local `blue audit` tooling for skill iteration and operational visibility
- stronger chat bootstrap, task feedback, failover visibility, and pending-state recovery so long-running conversations restore more faithfully
- clearer experimental runner selection plus better workspace-artifact/image-task/provider orchestration inside chat
- native productivity integrations for contacts/calendar with on-demand permission handling
- a Blue-owned `blue exec` surface plus tier-aware sandbox routing that prepares stronger per-platform isolation without exposing backend churn directly
- i18n naming/integrity cleanup plus failover-management follow-ups that improve maintainability and operational clarity
- bundle-based Harness dataset tooling and evaluation readiness work (datasets, specs, PinchBench/advisor bundle defaults, trajectory runs, remediation hints, and docs)
- native document tooling plus PDF/OCR foundations that support richer knowledge and document-driven workflows

That gives the `0.10.39` record a clear story: fewer fragmented advanced workflows, better repair/recovery context, richer native productivity/document surfaces, steadier operator feedback, lower-friction evaluation imports, and a more explicit Blue-owned path for controlled execution.
