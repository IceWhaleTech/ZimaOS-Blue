## 概述

本文档定义了 v0.10.6 Provider Pool 功能的分步实现计划，确保与 v0.10.5 API Proxy Sidecar 的修改隔离。

### 与 v0.10.5 的关系

| 组件 | v0.10.5 (Proxy Sidecar) | v0.10.6 (Provider Pool) |
|------|-------------------------|-------------------------|
| 位置 | `internal/proxy/` | `internal/providerpool/` |
| 职责 | API 请求代理、安全拦截 | Provider 管理、模型路由 |
| 依赖 | 使用 Provider Pool | 被 Proxy Sidecar 使用 |

**关键隔离点**:
- v0.10.6 创建独立的 `internal/providerpool/` 包
- 不修改现有的 `internal/providers/` 代码
- 不修改现有的 `internal/llm/` 代码
- 通过接口与现有代码集成

## 与 v0.10.5 的集成点

当 v0.10.5 Proxy Sidecar 实现后，集成方式:

```go
// Proxy Sidecar 使用 Provider Pool
type ProxySidecar struct {
    pool *providerpool.Pool  // 使用 Provider Pool 获取路由
}

func (p *ProxySidecar) HandleRequest(req *Request) (*Response, error) {
    // 1. 使用 Provider Pool 路由
    route, err := p.pool.Router.Route(req.Model, RoutingStrategyPriority)

    // 2. 转发请求到选定的 Provider
    return p.forward(route.Provider, req)
}
```

## 风险和缓解

| 风险 | 影响 | 缓解措施 |
|------|------|----------|
| 与现有 LLM 代码冲突 | 高 | 创建独立包，通过接口集成 |

| 模型列表 API 变更 | 中 | 缓存 + 错误处理 |
| 性能影响 | 低 | 使用对象池和缓存 |
