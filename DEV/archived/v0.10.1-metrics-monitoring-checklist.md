### 5. Storage and Aggregation (Phase 5)

**Goal**: Implement InfluxDB-based persistent storage with continuous sampling and automatic retention.

#### Design Decisions
- **InfluxDB** for time-series data storage (lightweight, built-in retention policies)
- **Continuous Queries** for automatic downsampling
- **Minimal Storage** - only keep essential metrics, auto-cleanup old data
- **Retention Policies**:
  - Raw data: 1 hour (10s intervals)
  - 1-minute aggregates: 24 hours
  - 5-minute aggregates: 7 days
  - 1-hour aggregates: 30 days
  - 1-day aggregates: 1 year

#### Backend Tasks - Storage Interface
- [ ] **Storage Interface** (`server/internal/metrics/store.go`)
  - [ ] MetricsStore interface (Write, WritePoint, Query, Close)
  - [ ] Point struct (Measurement, Tags, Fields, Timestamp)
  - [ ] QueryResult struct (Series, Values)

#### Backend Tasks - InfluxDB Storage

  - [ ] WritePoint - write single metric point
