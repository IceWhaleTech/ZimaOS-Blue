## Overview

v0.10.37 is a narrow follow-up release after the larger runtime-convergence work recorded in v0.10.36.

This version does not try to reopen the whole architecture. Instead, it closes a specific remaining gap:

- Blue had a stronger shared runtime bundle than before, but it still lacked a clearly exposed single in-process runtime trace contract
- Harness had tracing and observer groundwork, but operator-facing surfaces could not yet consume that runtime trace directly
- Subagent execution had stronger shared wiring, but the isolation story still needed clearer metadata and lifecycle boundaries
- Progressive loading existed as a desired skill-system direction, but runtime-safe budget hooks and regression gates were not yet explicit enough

The release intent for v0.10.37 is therefore simple:

- Keep chat, agent, harness, research, subagent, approval, and memory behavior externally stable
- Add only additive contract fields and internal runtime providers
- Expose runtime trace data through the existing harness control plane
- Improve runtime guardrails and regression visibility without introducing a new platform model

The same version window later absorbed a second, lower-risk polish wave:

- runtime coordination and skill-exposure follow-ups
- external agent configuration and multilingual settings coverage
- managed Agentcore Runner beta plus Harness optimization triggers
- safer skill-install policy plus clearer plugin and skill-install feedback
- harness context-pack visibility and final Harness-to-Automation IA cleanup
- desktop-managed backup-restore restart handling
- chat recovery hardening plus channels, browser monitor, task workspace, and viewport polish across the web shell

Those later changes stayed inside the same release philosophy. They improve operator ergonomics and desktop behavior, but they do not reopen the main runtime model introduced earlier in the release.

A final gated follow-up also landed in the same version window after live non-regression evidence was available:

- tool schema on the migrated chat path was slimmed down to the `exec`-centric native surface
- discover-first routing became the shipped default for eligible skills under the default settings
- `web_query` became the canonical public web skill and tool name, while `web_search` and related names remain compatibility aliases only
- the old adapter and alias paths remain as fallback or compatibility surfaces, not the main exposed path

## Why This Version Exists

The remaining architectural gap after v0.10.36 was not only route size or runtime wiring. It was contract clarity.

At the end of the previous cycle:

- Harness already had runtime observers and trace collection primitives
- Skill selection had moved closer to contract-based behavior
- The runtime bundle existed as the correct integration center
- Operator surfaces still primarily consumed evidence fragments rather than a single trace-oriented runtime contract

v0.10.37 addresses that gap by making runtime traces a first-class additive output of the harness control plane while also hardening the surrounding execution boundaries.

As the window continued, the release also became the place where several adjacent operator-facing follow-ups were finished: skill exposure became more explicit, external-agent settings landed, managed optimization surfaced in Settings, install policy and contract feedback became clearer, restore behavior became desktop-aware, chat recovery logic hardened, and the channel/browser/task shell received late navigation polish.

## Release Notes Draft

### v0.10.37 - Runtime Trace Contract, Skill+Exec Cutover Closeout, Operator Polish, and Desktop Restore Hardening

v0.10.37 is a targeted follow-up to the broader runtime-convergence work. It keeps the public REST and SSE families stable, but it makes the internal contract materially clearer and closes the gated tool-to-skill migration in the same release window.

What users and operators gain in practice:

- Harness-linked runs now expose runtime traces more directly
- The harness detail UI can show execution stages, lifecycle events, and trace artifacts
- Harness detail and comparison views can now surface context-pack summaries and per-run selection snapshots
- Subagent execution carries clearer isolation and parent-child runtime semantics
- Skill selection has better progressive-loading budget observability
- Eligible chat requests now route through discover-first canonical skills and collapse to an `exec`-only native surface by default
- `web_query` is now the canonical public web skill or tool name, while `web_search` remains compatibility-only
- Runtime contract drift is more strongly guarded in CI
- External Agents can be configured from Settings instead of only through manual setup
- Skill installation outcomes are clearer through localized in-product result feedback, contract metadata, and explicit high-risk override warnings
- Settings now includes Agentcore Runner beta controls plus last optimization evidence
- Chat and IM flows can recover malformed pseudo tool-call text and steer research or write workflows back toward saved deliverables
- Channels, browser monitor, and task surfaces are more informative and safer to interact with
- Backup restore can hand restart ownership to the desktop shell when required
- Mobile and settings-heavy surfaces are lighter through improved viewport handling, async loading, and back-to-top affordances
- Heartbeat-only operator and documentation surfaces no longer imply a still-supported periodic LLM poller

What this version intentionally does not do:

- It does not yet eliminate the independent research lane
- It does not remove all compatibility aliases or fallback adapters after cutover
- It does not yet graduate Agentcore Runner from an experimental local beta into a general remote optimization platform
- It does not yet make skill frontmatter and gateway-install contracts fully first-class
