## Overview

v0.10.35 was a high-surface-area integration release. Instead of focusing on only one subsystem, it pushed several adjacent tracks forward at the same time:

- Harness moved from basic grouping into a broader v3 operational model
- Browser execution gained relay and monitoring surfaces
- Chat became more artifact-aware and better prepared for document, media, and research-heavy workflows
- Deep-research, conversion, media fallback, and composition pipelines all expanded together
- The tool layer grew significantly, especially around web, office, and search workflows
- Auth/settings behavior was cleaned up so the web application could manage the larger runtime more reliably

## Strategic Context

The planning work around this window maps closely to what landed in the release:

- Harness was being pushed toward a user-facing projection layer on top of internal runs and groups. This release clearly lands task-projection primitives and related UI support.
- Temporary evaluation, process observations, verifier labels, and richer scorecards were being positioned as first-class harness concepts. The new evaluation and verifier work aligns strongly with that direction.
- Context compression was being redesigned around latest-intent protection, carry-over demotion, explicit modes, and deterministic gates. This release visibly lands that engine, its tests, and its settings surface.
- Deep research was being reshaped into a tighter single-bubble timeline experience. The dedicated timeline card in this release is a direct expression of that design.
- Media fallback was being expanded into slide-aware rendering, native local video fallback, and scene-composition primitives. The `fallback_slide`, `fallback_native_video`, `scenecompose`, and `slidespec` additions match that strategic direction.
- Browser and retrieval work was moving toward relay-backed observation, layered retrieval, and richer monitoring. The relay, monitor widget, and larger web/webfetch expansion line up with that arc.
- Marketplace and local-tooling plans emphasized batch refresh, dynamic visibility, and runtime-managed search capability. The skill-market storage/service growth and ripgrep tooling in this release fit that pattern.
- Chat UX planning was also moving toward stronger streaming, recovery, and long-message handling. The larger chat component and store changes in this window are consistent with that trajectory, even where exact UX completion cannot be proven solely from the archive surface.

## Implementation Notes

### Harness and Governance Notes

- The harness package moved beyond grouped execution into evaluation, verification, proposal intake, and user-facing task projection.
- The web surface reflected that shift through the harness tab, scorecard diagnostics, policy-management flows, and large locale-overlay additions.
- `docs/harness-v3.md` indicates that this version window was not just UI polish; it reflected a broader product-level harness model change.

### Browser and Monitoring Notes

- Browser relay introduced a more explicit runtime path for browser-backed flows instead of keeping all browser behavior in a single service path.
- Site-pattern logic, session-lifecycle tests, and the browser monitor widget suggest the browser subsystem was being prepared for longer-lived and more observable sessions.
- This made browser behavior more governable from both runtime and UI perspectives.

### Chat, Research, and Artifact Notes

- Chat orchestration became more artifact-aware through dedicated workspace and research orchestration modules.
- Persistence, media understanding, and intent matching all expanded in the same window, which points to a broader shift toward richer multimodal and task-oriented chat execution.
- Deep-research calibration, cue matching, and localized verification show that research work was maturing in both backend behavior and user-visible output quality.

### Tooling and Conversion Notes

- The tool layer grew substantially with unified web access, web retrieval, video-oriented web behavior, native/document-aware fetch, office document handling, and ripgrep-based search.
- The conversion pipeline gained stronger local handling for documents and spreadsheets, plus tabular summaries to support agent-readable outputs.
- Media generation also deepened with slide-native fallback, native video fallback, scene composition, and slide-spec planning foundations.

### Web Product Notes

- `HarnessGroupsView`, `HarnessGroupDetailView`, `ChatMessage`, and `CardDeepResearchTimeline` were all expanded to present richer runtime state to users.
- `BrowserMonitorWidget` and `authStorage.ts` are representative of the window's broader theme: make complex backend behavior visible and manageable from the UI.
- Settings also became more operational, exposing context-compression, theme, close behavior, and related runtime controls.

## User-Facing Outcomes

- Harness activity became more understandable from the UI through richer group detail, diagnostics, and projected task state.
- Deep-research progress became easier to follow as a timeline-style experience instead of a loose collection of individual progress cards.
- Browser-backed work became more observable via monitor surfaces instead of feeling like an opaque background subsystem.
- Settings became more operational, exposing context-compression behavior, theme controls, and close-behavior preferences.
- Chat became better prepared to present artifacts, research outputs, and richer task state without relying on a plain text-only interaction model.

## Follow-up Signals

- Some plan files from the same period are broader than what can be proven as completed in the exact `0.10.35` release window. This is especially true for mixed-kernel browser routing, layered retrieval memory, and some chat streaming UX details.
- Plans dated after the `0.10.35` bump on 2026-03-24 were not treated as implemented scope in this archive unless there was clear matching code in the version window.
- The strongest implemented matches are harness task projection, harness evaluation/verification, context compression, deep-research timeline presentation, scene-compose/media fallback, ripgrep tooling, and auth-storage cleanup.

## Deferred or Still In Motion

- Browser relay and monitoring landed clearly, but a fully mature multi-kernel routing strategy was still broader than what can be safely claimed for this version alone.
- Retrieval and web tooling expanded dramatically, yet per-host strategy memory and deeper adaptive orchestration appear to remain part of the continuing direction rather than a fully completed endpoint here.
- Chat UX hardening was clearly underway, but the entire streaming/recovery/segmentation vision was likely still evolving across adjacent changes.
- Media fallback moved much closer to a composed local pipeline, though the overall media-generation stack was still in active architectural growth rather than steady-state convergence.

## Summary

v0.10.35 was a large integration release.
