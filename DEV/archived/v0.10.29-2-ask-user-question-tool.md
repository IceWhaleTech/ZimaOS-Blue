# v0.10.29-2 AskUserQuestion Built-in Tool

**Version**: 0.10.29
**Created**: 2026-02-25

---

## Overview

Add `ask_user_question` as a first-class built-in tool that the LLM can call to ask the user
questions during a conversation or agent task. Supports single-select, multi-select, multiple
questions in one call (frontend renders as tabs), and an unattended/silent mode that auto-answers
with defaults or skips.

## Architecture

### Data Flow

```
LLM calls ask_user_question tool
  → Backend: AskUserQuestionTool.Execute()
    → If unattended mode: return default answers immediately (no SSE, no wait)
    → If interactive mode:
      1. Publish SSE event "ask_user_question" with questions payload
      2. Block on answer channel (with timeout)
      3. Frontend renders AskUserQuestionDialog (tab UI for multiple questions)
      4. User submits answers → REST POST /api/v1/ask-user-question/:id/answer
      5. Backend resolves channel → returns answers as tool result to LLM
```

### Existing Patterns Reused

- **ApprovalManager pattern** (`exec_approval.go`): SSE publish → block on channel → REST resolve.
  The new `QuestionManager` follows the same pattern but with richer payloads.
- **Tool interface** (`registry.go`): Standard `Tool` interface with `Definition()` + `Execute()`.
- **Context helpers** (`context.go`): `GetUserID()`, `GetSessionID()`, `GetChannel()` for scoping.
- **SSE Broker** (`sse/broker.go`): `Publish(userID, eventType, data)` for real-time push.
- **useEventStream** (`composables/useEventStream.ts`): Global SSE listener dispatches to stores.

## Phase 1: Backend — Tool + QuestionManager

### 1.1 QuestionManager (`server/internal/tools/question_manager.go`)

```go
// QuestionManager handles the ask-user-question flow via SSE.
type QuestionManager struct {
    broker  *sse.Broker
    mu      sync.Mutex
    pending map[string]*pendingQuestion
    timeout time.Duration
    silent  func() bool // returns true when unattended mode is active
}

type pendingQuestion struct {
    ch      chan []QuestionAnswerResult
    created time.Time
}

// QuestionRequest is the SSE payload sent to the frontend.
type QuestionRequest struct {
    ID        string          `json:"id"`
    Questions []QuestionItem  `json:"questions"`
    UserID    string          `json:"user_id"`
    SessionID string          `json:"session_id,omitempty"`
    ExpiresAt int64           `json:"expires_at"` // Unix ms
}

// QuestionItem describes a single question (one tab in the UI).
type QuestionItem struct {
    ID          string           `json:"id"`
    Question    string           `json:"question"`
    Header      string           `json:"header"`                  // short tab label (max 12 chars)
    Options     []QuestionOption `json:"options,omitempty"`
    MultiSelect bool             `json:"multi_select,omitempty"`
}

// QuestionOption is a selectable option.
type QuestionOption struct {
    Label       string `json:"label"`
    Description string `json:"description,omitempty"`
    Value       string `json:"value,omitempty"` // defaults to label if empty
}

// QuestionAnswerResult is the user's answer to one question.
type QuestionAnswerResult struct {
    QuestionID string   `json:"question_id"`
    Selected   []string `json:"selected"`              // selected option labels/values
    OtherText  string   `json:"other_text,omitempty"`  // free-text "Other" input
}
```

Key methods:
- `NewQuestionManager(broker, silentFunc, timeout)`
- `AskQuestions(ctx, userID, sessionID, questions) ([]QuestionAnswerResult, error)` — publishes SSE, blocks on channel
- `ResolveAnswer(id string, answers []QuestionAnswerResult) bool` — called by REST endpoint
- `IsSilent() bool` — delegates to `silent` func

Silent mode behavior: When `IsSilent()` returns true, `AskQuestions()` returns immediately with
default answers (first option selected for each question, empty `other_text`). No SSE event is
published, no blocking.

### 1.2 AskUserQuestionTool (`server/internal/tools/ask_user_question.go`)

Implements `tools.Tool` interface.

```go
type AskUserQuestionTool struct {
    mgr *QuestionManager
}
```

Tool definition name: `ask_user_question`

Parameters schema:
```json
{
  "type": "object",
  "properties": {
    "questions": {
      "type": "array",
      "description": "1-4 questions to ask the user. Each rendered as a tab.",
      "items": {
        "type": "object",
        "properties": {
          "question": { "type": "string", "description": "The question text" },
          "header": { "type": "string", "description": "Short tab label (max 12 chars)" },
          "options": {
            "type": "array",
            "description": "2-4 selectable options. An 'Other' free-text option is always appended automatically.",
            "items": {
              "type": "object",
              "properties": {
                "label": { "type": "string" },
                "description": { "type": "string" }
              },
              "required": ["label"]
            }
          },
          "multi_select": { "type": "boolean", "description": "Allow multiple selections (default false)" }
        },
        "required": ["question", "header", "options"]
      }
    }
  },
  "required": ["questions"]
}
```

Execute flow:
1. Parse `questions` array from args
2. Validate: 1-4 questions, each with 2-4 options, header ≤ 12 chars
3. Call `mgr.AskQuestions(ctx, userID, sessionID, questions)`
4. Return answers as JSON tool result

### 1.4 REST Endpoint for Answer Submission

In `bootstrap/routes.go`, add:
```go
// POST /api/v1/ask-user-question/:id/answer
askGroup := apiProtected.Group("/v1/ask-user-question")
askGroup.POST("/:id/answer", func(c echo.Context) error {
    id := c.Param("id")
    var body struct {
        Answers []tools.QuestionAnswerResult `json:"answers"`
    }
    if err := c.Bind(&body); err != nil {
        return c.JSON(400, map[string]string{"error": "invalid body"})
    }
    if !questionMgr.ResolveAnswer(id, body.Answers) {
        return c.JSON(404, map[string]string{"error": "question not found or expired"})
    }
    return c.JSON(200, map[string]string{"status": "ok"})
})
```

### 1.6 Agent Runner Integration

The agent runner already uses `tools.Executor` to call tools. Since `ask_user_question` is
registered in the same `tools.Registry`, the agent can call it naturally via tool calls.
No special wiring needed — the tool blocks until the user answers (or silent mode auto-answers).

The existing `askQueues` field in `Runner` (already added to task.go/runner.go) can be removed
or repurposed — the `QuestionManager` handles the blocking/resolution centrally.

```ts
// Ask-user-question state
const pendingQuestion = ref<{
    id: string
    questions: Array<{
        id: string
        question: string
        header: string
        options: Array<{ label: string; description?: string; value?: string }>
        multi_select?: boolean
    }>
    expires_at: number
} | null>(null)

function setPendingQuestion(data: any) {
    pendingQuestion.value = data
}

async function submitQuestionAnswers(answers: QuestionAnswerResult[]) {
    if (!pendingQuestion.value) return
    const id = pendingQuestion.value.id
    try {
        await api.post(`/ask-user-question/${id}/answer`, { answers })
    } finally {
        pendingQuestion.value = null
    }
}
```

### 2.3 AskUserQuestionDialog Component (`web/src/components/AskUserQuestionDialog.vue`)

- Teleport to body (same pattern as ToolApprovalDialog)
- Modal overlay with card
- Tab bar at top: one tab per question, using `header` as tab label
- Active tab shows:
  - Question text
  - Options as radio buttons (single-select) or checkboxes (multi-select)
  - "Other" free-text input always appended as last option
- Submit button at bottom (disabled until all required questions have at least one selection)
- Auto-dismiss on timeout (show countdown timer)
- Keyboard: Enter to submit, Escape to dismiss (selects defaults)

Tab UI behavior:
- Tabs are horizontally scrollable if > 3
- Active tab has accent underline
- Badge on tab shows checkmark when answered
- User can switch between tabs freely before submitting
- All answers submitted together in one POST

## Phase 3: Unattended / Silent Mode

### 3.1 Settings

Already exists: `AgentAutoConfirm *bool` in `Settings` struct. When true, the `QuestionManager`
auto-answers with defaults (first option for each question).

### 3.2 Silent Mode Behavior

- `QuestionManager.IsSilent()` checks `silentFunc()` (wired to `settingsHandler.GetAgentAutoConfirm()`)
- When silent: `AskQuestions()` returns immediately with default answers:
  - Single-select: first option selected
  - Multi-select: first option selected
  - No "Other" text
- Tool result includes `"silent": true` flag so the LLM knows answers were auto-generated
- No SSE event published, no blocking

### 3.3 Channel-Aware Behavior

For non-web channels (Telegram, Discord, etc.) where modal dialogs aren't possible:
- `GetChannel(ctx)` returns channel name
- If channel is not "web" and not empty, fall back to silent mode behavior
- This ensures the tool doesn't block indefinitely on channels without UI

## Phase 4: System Prompt Guidance

### 4.1 System Prompt Injection

In `systemprompt.go`, add `buildAskUserQuestionGuidance()`:

```
## ask_user_question Tool

You have access to the `ask_user_question` tool to ask the user questions when you need
clarification or input. Use it when:
- You need to choose between multiple valid approaches
- User preferences matter for the outcome
- Requirements are ambiguous

Guidelines:
- Ask 1-4 questions at a time (each becomes a tab in the UI)
- Provide 2-4 clear, distinct options per question
- Keep headers short (max 12 chars) — they're tab labels
- Users can always type a custom "Other" answer
- Use multi_select only when choices aren't mutually exclusive
- Don't ask questions you can answer yourself from context
```

Only inject when the tool is registered (check registry).
