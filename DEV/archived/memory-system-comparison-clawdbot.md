# Memory System Comparison: ZimaOS-Echo vs Clawdbot

> 对比日期: 2026-02-03
> 参考文章: Clawdbot 记忆管理系统分析

## 架构对比

| 特性 | Clawdbot | ZimaOS-Echo | 差距 |
|------|----------|-------------|------|
| **存储格式** | Markdown 文件 (透明可编辑) | SQLite + 向量嵌入 (不透明) | ⚠️ 需改进 |
| **记忆分层** | 双层: 每日日志 + 长期记忆 | 单层: 统一 memory_chunks | ⚠️ 需改进 |
| **搜索方式** | 混合搜索 (向量70% + BM25 30%) | 混合搜索 (向量70% + 关键词30%) | ✅ 已对齐 |
| **索引存储** | sqlite-vec + FTS5 | SQLite + FTS5 | ✅ 已对齐 |
| **分块策略** | 400 Token/块, 80 Token 重叠 | 可配置, 有重叠 | ✅ 已对齐 |
| **透明度** | 用户可直接编辑 MD 文件 | 仅通过 API 操作 | ⚠️ 需改进 |
| **多智能体** | 每个智能体独立记忆隔离 | 暂无多智能体隔离 | ⚠️ 需改进 |
| **压缩机制** | 有压缩 + 记忆刷新钩子 | 无 | ❌ 缺失 |
| **会话钩子** | /new 时自动保存上下文 | 无 | ❌ 缺失 |
| **后端切换** | 无 (仅本地) | 本地 ↔ Supermemory | ✅ 优势 |
| **自动清理** | 无明确策略 | 有 (保留80%最大值) | ✅ 优势 |

## Clawdbot 核心设计理念

### 1. 上下文 vs 记忆

```
上下文 = 系统提示词 + 对话历史 + 工具结果 + 附件
  - 转瞬即逝: 只在单次请求存在
  - 有边界: 受限于上下文窗口
  - 昂贵: 每个 Token 都算钱

记忆 = MEMORY.md + memory/*.md + 会话实录
  - 持久: 重启后仍在
  - 无边界: 可无限增长
  - 便宜: 存储不花 API 钱
  - 可搜索: 建了索引
```

### 2. 双层记忆架构

```
~/clawd/
├── MEMORY.md              # 第2层: 长期精选知识
└── memory/
    ├── 2026-01-26.md      # 第1层: 今天的笔记
    ├── 2026-01-25.md      # 昨天的笔记
    └── ...
```

**第1层 - 每日日志**: 只增不减的每日笔记
**第2层 - 长期记忆**: 精选的持久知识库

### 3. 记忆工具

- `memory_search`: 语义搜索所有记忆文件
- `memory_get`: 读取特定文件的特定行
- 写入: 使用标准文件写入工具 (无专门 memory_write)

### 4. 索引机制

```
文件保存 → 文件监听器检测 → 分块 (400 Token, 80 重叠)
    → 嵌入生成 → SQLite 存储 (sqlite-vec + FTS5)
```

### 5. 混合搜索

```
finalScore = (0.7 * vectorScore) + (0.3 * textScore)
```

### 6. 压缩机制

- **自动压缩**: 接近上下文限制时触发
- **记忆刷新**: 压缩前自动保存重要信息到记忆文件
- **剪枝**: 修剪旧的工具输出

## ZimaOS-Echo 当前实现

### 已有功能

1. ✅ **混合搜索** (向量 + 关键词, 70/30 权重)
2. ✅ **FTS5 全文搜索**
3. ✅ **后端切换** (本地 ↔ Supermemory)
4. ✅ **自动清理策略** (超过最大值时清理)
5. ✅ **完整 API 接口**
6. ✅ **并发控制** (读写锁)
7. ✅ **元数据支持** (标签)

### 缺失功能

1. ❌ **双层记忆架构** (每日日志 + 长期知识)
2. ❌ **Markdown 透明存储** (用户可直接编辑)
3. ❌ **压缩前记忆刷新** (防止信息丢失)
4. ❌ **会话结束钩子** (自动保存上下文)
5. ❌ **多智能体记忆隔离**
6. ❌ **memory_search / memory_get 工具**

---

## 我们的优势

1. **后端灵活性**: 支持本地和云端 (Supermemory) 切换
2. **自动清理**: 有明确的清理策略, 防止无限增长
3. **统一服务接口**: UnifiedMemoryService 抽象
4. **API 完整性**: RESTful API 设计完善
