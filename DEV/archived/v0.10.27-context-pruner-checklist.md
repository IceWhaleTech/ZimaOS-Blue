# SWE-Pruner ONNX 本地推理 + 模型下载进度

## 概述

将 code-pruner (ayanami-kitasan/code-pruner) 模型集成到 ZimaOS-Blue，支持：
1. 前端点击下载模型（显示进度条、速度、ETA）
2. Go 后端用 onnxruntime_go (CGo) 加载 ONNX 模型做本地推理
3. 作为 pruner 的新 backend: `"onnx"`

## 模型架构分析

- 基座: Qwen3-Reranker-0.6B (transformer)
- 头部: CRF compression head + multi-layer fusion
- 输入: input_ids + attention_mask → [batch, seq_len]
- 输出: token_logits [batch, seq_len] (每个 token 的保留/裁剪分数)
- Tokenizer: BPE (vocab.json + merges.txt, 来自 Qwen3)
- 模型大小: safetensors 1.35GB → ONNX 估计 ~1.4GB (FP32) 或 ~700MB (FP16)

## 实施计划

### Phase 1: ONNX 模型导出 (Python 脚本，不进 Go 代码)

创建 `scripts/export_pruner_onnx.py`:
- 加载 HuggingFace 模型 (SwePrunerForCodeCompression)
- 用 `torch.onnx.export()` 导出为 ONNX
- 输入: input_ids [1, 8192], attention_mask [1, 8192]
- 输出: token_logits [1, 8192]
- 导出 FP16 版本减小体积
- 将导出的 ONNX 文件上传到可下载的 URL (HuggingFace/GitHub Release)

### Phase 2: Go BPE Tokenizer

新建 `server/internal/pruner/tokenizer.go`:
- 实现 BPE tokenizer (加载 vocab.json + merges.txt)
- 支持 Qwen3 的 special tokens (chat template 中的 prefix/suffix)
- Encode: text → token_ids
- 不需要 Decode (只需要 token→line 的映射)
- 参考 swe-pruner 的 `build_input_for_llm()` 构建输入格式

### Phase 3: Go ONNX Runtime Backend

新建 `server/internal/pruner/onnx_backend.go` (build tag: `//go:build onnx`):
- 依赖: `github.com/yalue/onnxruntime_go`
- 加载 ONNX 模型文件
- 实现 `Backend` 接口 (Prune/Health/Close)
- 推理流程:
  1. Tokenize 输入 (query + code)
  2. 构建 input_ids + attention_mask tensors
  3. 运行 ONNX 推理 → token_logits
  4. 将 token scores 聚合到行级别
  5. 按 threshold 裁剪行
- 需要 ONNX Runtime 共享库 (.dylib/.so/.dll)

### Phase 4: 模型下载管理器

新建 `server/internal/pruner/model_manager.go`:
- 复用 whisper 的下载模式 (参考 `stt/whisper_models.go`)
- `PrunerModelManager` struct:
  - 下载 ONNX 模型文件 + tokenizer 文件 (vocab.json, merges.txt, config.json)
  - 进度追踪: percentage, speed, ETA
  - 取消下载支持
  - 模型状态: not_downloaded / downloading / ready
- 模型存储路径: `{dataDir}/pruner-models/`
- 下载源: HuggingFace (或自定义 URL)

### Phase 5: API 端点

扩展 `server/internal/pruner/handler.go`:
- `POST /api/v1/proxy/pruner/model/download` — 开始下载

### Phase 6: 前端 UI

  - 已下载 → 显示 ✓ 已就绪 + 模型信息

### Phase 7: Bootstrap 集成

## 风险 & 注意事项

1. ONNX 导出: CRF head 的 Viterbi 解码可能不支持直接 ONNX 导出，可能需要拆分为 backbone + head 两个 ONNX 模型，CRF 解码在 Go 侧实现
2. Tokenizer: Go 实现 BPE 需要处理 Unicode、byte-level BPE 等细节，可考虑用 `github.com/daulet/tokenizers` (HuggingFace tokenizers 的 Go binding)
3. ONNX Runtime 共享库: 需要用户安装或随应用分发 (~50-200MB)
4. 内存: 0.6B 模型 FP16 约需 1.2GB RAM
5. 首次推理延迟: ONNX 模型加载 + 优化可能需要几秒
