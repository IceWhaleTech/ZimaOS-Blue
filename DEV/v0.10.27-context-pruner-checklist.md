## Phase 7: BM25 + Segment Indexing (P1) ✅

**Core Scoring:**
- [x] 7.1 Implement BM25Scorer with configurable k1, b parameters — `bm25.go`
- [x] 7.2 Implement code tokenizer (camelCase/snake_case splitting, lowercasing) — `bm25.go:codeTokenize()`
- [x] 7.3 Implement pluggable Scorer interface (BM25 default, TF-IDF fallback) — `bm25.go:Scorer`

**Indexing:**
- [x] 7.4 Implement Segmenter: split code into function/class/block segments — `segmenter.go`
- [x] 7.5 Support Go, Python, JS/TS, Rust, Java segment detection — `segmenter.go:segmentPatterns`
- [x] 7.6 Implement segment-level token pre-computation — `segmenter.go:Segmentize()`

**Caching:**
- [x] 7.7 Implement LRU in-memory score cache — `cache.go:LRUScoreCache`
- [x] 7.8 Implement cache key generation (file hash + query hash) — `cache.go:CacheKey()`
- [ ] 7.9 Optional disk persistence for cache (deferred — not needed for MVP)

**Pipeline:**
- [x] 7.10 Implement Top-K selector with token budget — `pipeline.go:SelectTopK()`
- [x] 7.11 Implement rule-based weight boosting layer — `pipeline.go:BoostScores()`
- [x] 7.12 Wire BM25 scorer into existing Middleware as pluggable backend — `pruner.go:NewBackend("bm25")`

## Phase 8: Validation & Benchmarking (P1) ✅

- [x] 8.1 Benchmark harness: latency on 1k/5k/10k LOC files — `benchmark_test.go`
- [x] 8.2 Recall@K computation against full-context baseline — Local: 1.00, BM25: 0.51
- [x] 8.3 Token reduction calculation — Local: ~59%, BM25: ~47%
- [x] 8.4 Memory profiling — BM25 uses 99% fewer allocs than Local at 10k LOC

**Benchmark Results (Apple M2) — After Optimization:**

| Backend | 1k LOC | 5k LOC | 10k LOC | Allocs/op (10k) |
|---------|--------|--------|---------|-----------------|
| Local   | 1.4ms  | 7.2ms  | 15.1ms  | 200,017         |
| BM25    | 0.7ms  | 3.3ms  | 6.8ms   | 827             |

| Backend | Token Reduction | Recall@K |
|---------|----------------|----------|
| Local   | ~59%           | 1.00     |
| BM25    | ~47%           | 0.51     |

## Phase 8b: Scoring Optimization ✅

- [x] 8b.1 Query expansion: `tokenize()` now uses `codeTokenize()` for camelCase/snake_case splitting
- [x] 8b.2 BM25 token budget: changed from `1.0 - threshold*0.5` to `1.0 - threshold` for more aggressive pruning
- [x] 8b.3 Name-match boost: `BoostScoresWithQuery()` gives 1.5x multiplier when segment name matches query terms
- [x] 8b.4 Coverage constraint test: verified Top-K selector handles tight budgets gracefully
