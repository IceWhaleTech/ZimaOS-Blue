# PRD: IR-Based Media Generation Pipeline

**Version**: 0.10.28-1
**Author**: ZimaOS-Blue Team
**Status**: Draft
**Created**: 2026-02-23

---

## 1. Overview

### 1.1 Problem Statement

The current media generation flow routes through the LLM chat pipeline:

```
User message → LLM → tool_use(image_generate/video_generate) → MediaManager → Provider → Result
```

This has several issues:

1. **Unnecessary LLM round-trip** — generating an image from "draw me a cat" doesn't need LLM reasoning; it wastes tokens and adds 2-5s latency
2. **Tool-use fragility** — the LLM may not always invoke the correct tool, or may hallucinate parameters
3. **No user control** — users can't choose the model, resolution, or style before generation starts
4. **No graceful interruption** — once the LLM decides to generate, there's no way to cancel and fall back to chat
5. **Limited model catalog** — MuleRouter now offers 25+ models across 4 vendors; the tool-use approach can't expose this richness

### 1.2 Proposed Solution

Replace the LLM tool-use path with an **Intent Recognition (IR) classifier** that runs _before_ the message enters the LLM pipeline:

```
User message → IR Classifier → [Media Intent?]
  YES → Interactive Parameter UI → Direct MediaManager call → Placeholder + Progress → Result
  NO  → Normal LLM chat pipeline
```

### 1.3 Goals

1. Detect media generation intent without calling the LLM (zero-token classification)
2. Present an interactive parameter selection UI before generation starts
3. Route directly to `MediaManager` bypassing the chat/tool-use pipeline
4. Show a real-time placeholder (progress bar, thumbnail preview) during generation
5. Allow users to cancel generation and fall back to normal chat at any time
6. Expose the full MuleRouter model catalog (25+ models across text-to-image, text-to-video, image-to-video, image editing)

### 1.4 Non-Goals

- This does NOT replace the existing tool-use path (kept as fallback for complex multi-step workflows)
- This does NOT add new media providers — it leverages existing `MediaManager` + `MuleRouterProvider`
- This does NOT handle audio generation (separate feature)
- No prompt engineering or enhancement in this version (MuleRouter's `prompt_extend` handles this)

### 1.5 Target Users

| User | Need |
|------|------|
| End users | Fast, intuitive media generation with model/parameter choice |
| Power users | Fine-grained control over resolution, duration, style, seed |
| Developers | Clean API separation between chat and media generation paths |

## 2. Intent Classification (IR Layer)

### 2.1 Media Intent Categories

| Category | ID | Description | Requires Image Input |
|----------|----|-------------|---------------------|
| Text-to-Image | `t2i` | Generate image from text prompt | No |
| Text-to-Video | `t2v` | Generate video from text prompt | No |
| Image-to-Video | `i2v` | Animate a reference image | Yes |
| Image Editing | `i2i` | Modify/transform an existing image | Yes |
| Keyframe-to-Video | `kf2v` | Generate video from first+last frame | Yes (2 images) |

### 2.2 Classification Approach

Use a **rule-based IR classifier** (no LLM needed) with two layers:

**Layer 1: Keyword + Pattern Matching**
- Regex patterns for explicit generation requests across all 27 supported locales
- Action verbs + media nouns per language family:

| Language Group | Locales | Action Verbs (generate/create/draw) | Media Nouns (image/video) |
|---------------|---------|-------------------------------------|--------------------------|
| English | en-US, en-GB, ga-IE | `generate\|create\|draw\|paint\|make\|produce\|render` | `image\|picture\|photo\|illustration\|video\|animation\|clip` |
| Chinese | zh-CN, zh-TW | `生成\|画\|绘\|制作\|创建\|做\|弄` | `图\|图片\|照片\|图像\|视频\|动画\|影片` |
| Japanese | ja-JP | `生成\|描く\|作る\|作成\|描いて\|書いて` | `画像\|写真\|イラスト\|動画\|ビデオ\|映像\|アニメ` |
| Korean | ko-KR | `생성\|그려\|만들\|그리다\|제작` | `이미지\|사진\|그림\|영상\|동영상\|비디오` |
| German | de-DE | `erstellen\|erzeugen\|zeichnen\|malen\|generieren` | `Bild\|Foto\|Illustration\|Video\|Animation` |
| French | fr-FR | `générer\|créer\|dessiner\|peindre\|produire` | `image\|photo\|illustration\|vidéo\|animation` |
| Spanish | es-ES, ca-ES | `generar\|crear\|dibujar\|pintar\|producir` | `imagen\|foto\|ilustración\|vídeo\|animación` |
| Portuguese | pt-BR, pt-PT | `gerar\|criar\|desenhar\|pintar\|produzir` | `imagem\|foto\|ilustração\|vídeo\|animação` |
| Italian | it-IT | `generare\|creare\|disegnare\|dipingere\|produrre` | `immagine\|foto\|illustrazione\|video\|animazione` |
| Dutch | nl-NL | `genereren\|maken\|tekenen\|schilderen` | `afbeelding\|foto\|illustratie\|video\|animatie` |
| Russian | ru-RU | `сгенерировать\|создать\|нарисовать\|сделать` | `изображение\|картинку\|фото\|видео\|анимацию` |
| Polish | pl-PL | `wygeneruj\|stwórz\|narysuj\|zrób` | `obraz\|zdjęcie\|ilustrację\|wideo\|animację` |
| Swedish | sv-SE | `generera\|skapa\|rita\|måla` | `bild\|foto\|illustration\|video\|animation` |
| Danish | da-DK | `generer\|opret\|tegn\|mal` | `billede\|foto\|illustration\|video\|animation` |
| Norwegian | nb-NO | `generer\|lag\|tegn\|mal` | `bilde\|foto\|illustrasjon\|video\|animasjon` |
| Czech | cs-CZ | `vygeneruj\|vytvoř\|nakresli` | `obrázek\|fotku\|ilustraci\|video\|animaci` |
| Slovak | sk-SK | `vygeneruj\|vytvor\|nakresli` | `obrázok\|fotku\|ilustráciu\|video\|animáciu` |
| Hungarian | hu-HU | `generálj\|készíts\|rajzolj\|alkoss` | `képet\|fotót\|illusztrációt\|videót\|animációt` |
| Romanian | ro-RO | `generează\|creează\|desenează` | `imagine\|fotografie\|ilustrație\|video\|animație` |
| Greek | el-GR | `δημιούργησε\|ζωγράφισε\|φτιάξε` | `εικόνα\|φωτογραφία\|βίντεο\|κινούμενο` |
| Croatian | hr-HR | `generiraj\|stvori\|nacrtaj` | `sliku\|fotografiju\|ilustraciju\|video\|animaciju` |
| Malayalam | ml-IN | `സൃഷ്ടിക്കുക\|വരയ്ക്കുക\|ഉണ്ടാക്കുക` | `ചിത്രം\|ഫോട്ടോ\|വീഡിയോ\|ആനിമേഷൻ` |

- Negation filter (per-language): "don't generate", "不要生成", "描かないで", "nicht erstellen", etc. → NOT media intent
- Question filter: "how to generate images?", "怎么生成图片？", "画像の作り方" → NOT media intent (informational)
- Case-insensitive matching; Unicode-aware word boundaries

**Layer 2: Context Signal Boosting**
- User attached an image → boost `i2v` / `i2i` confidence
- User attached 2 images → boost `kf2v` confidence
- Keywords like "animate", "move", "come alive" + image → strong `i2v` signal
- Keywords like "edit", "change", "modify", "remove" + image → strong `i2i` signal
- Keywords like "wallpaper", "portrait", "landscape" without image → strong `t2i` signal

**Layer 3: Ambiguity Resolution**
- If confidence < threshold (e.g., 0.7), return `ambiguous` → show disambiguation UI
- If multiple categories match, rank by specificity and present top choices

### 2.3 IR Classifier API

```go
// server/internal/mediagen/ir.go

type MediaIntent struct {
    Category    string  // "t2i", "t2v", "i2v", "i2i", "kf2v"
    Confidence  float64 // 0.0 - 1.0
    Prompt      string  // extracted/cleaned prompt text
    HasImage    bool    // user provided reference image(s)
    ImageCount  int     // number of attached images
    Suggestions []ModelSuggestion // recommended models for this intent
}

type ModelSuggestion struct {
    ModelID     string
    ModelName   string
    Vendor      string
    Reason      string // why this model is suggested
    IsDefault   bool
}

func ClassifyMediaIntent(message string, hasImages bool, imageCount int, locale string) *MediaIntent
```

### 3.2 Model Selection Logic

When the IR classifier identifies an intent category, the system suggests models based on:

1. **Category match** — only show models that support the detected category
2. **Provider availability** — only show models from configured+enabled providers
3. **Locale preference** — CN users default to Alibaba models; others default to OpenAI/Google
4. **Quality vs Speed** — "spark" and "flash" variants are faster; "plus" and "max" are higher quality
5. **User history** — remember last-used model per category (stored in localStorage)

### 4.2 Parameter Definitions by Category

**t2i Parameters:**
- `model` — model selector (filtered by t2i capability)
- `size` — resolution (model-dependent options)
- `quality` — standard / hd (model-dependent)
- `style` — natural / vivid (model-dependent)
- `n` — number of images (1-4)
- `negative_prompt` — optional, collapsible "Advanced" section

**t2v Parameters:**
- `model` — model selector (filtered by t2v capability)
- `resolution` — 720P / 1080P
- `duration` — 5s / 10s
- `prompt_extend` — toggle (default on)
- `seed` — optional, in "Advanced" section

**i2v Parameters:**
- `model` — model selector (filtered by i2v capability)
- `resolution` — 720P / 1080P
- `duration` — 5s / 10s
- `audio` — auto / custom URL / none
- `prompt_extend` — toggle

**i2i Parameters:**
- `model` — model selector (filtered by i2i capability)
- `size` — output resolution
- `n` — number of outputs (1-6 for qwen-image-edit-max)

### 4.3 "Switch to Chat" Escape Hatch

The "Switch to Chat Instead" button:
1. Dismisses the parameter panel
2. Sends the original message through the normal LLM chat pipeline
3. The LLM may or may not invoke media tools — user gets full conversational control

This is critical for cases where the IR classifier is wrong (e.g., "draw me a diagram of the architecture" is NOT an image generation request).

## 5. Generation Pipeline (Direct Path)

### 5.1 Backend API

New endpoint that bypasses the chat pipeline entirely:

```
POST /api/media/generate
Content-Type: application/json

{
  "category": "t2i",           // from IR classification
  "prompt": "a cat on a rainbow",
  "model": "dall-e-3",         // user-selected
  "params": {                  // category-specific
    "size": "1024x1024",
    "quality": "hd",
    "n": 1
  },
  "reference_images": ["data:image/jpeg;base64,..."],  // for i2v/i2i
  "session_id": "abc123"       // to associate with chat session
}
```

Response (SSE stream):

```
event: status
data: {"task_id": "xxx", "status": "pending"}

event: progress
data: {"task_id": "xxx", "progress": 0.3}

event: progress
data: {"task_id": "xxx", "progress": 0.7}

event: complete
data: {"task_id": "xxx", "status": "succeeded", "results": [...]}
```

### 5.2 Backend Flow

```
POST /api/media/generate
  → Validate params
  → Map category + model → MediaRequest
  → MediaManager.Generate(req)
  → If sync (dall-e-3): return result immediately
  → If async: start SSE stream, poll until complete
  → Cache result locally (storage.go)
  → Generate thumbnail
  → Inject result into chat session as a "media card" message
```

### 5.3 Chat Session Integration

The generated media must appear in the chat history as if it were a normal assistant response. This allows:
- Scrollback to see previous generations
- The LLM to reference generated media in subsequent turns
- Export/share of the full conversation

Implementation: after generation completes, append a synthetic assistant message to the session with the media card markup (same format as current tool-use results).

   - [Try different model]

## 8. Implementation Phases

### Phase 1: IR Classifier (P0)
- Implement rule-based classifier in Go (`ir.go`)
- Support all 27 locales with per-language keyword tables (see Section 2.2)
- Unit tests with 100+ test cases covering all languages and edge cases
- `POST /api/media/classify` endpoint
- Client-side JS classifier (mirror of Go logic for zero-latency)

### Phase 2: Model Catalog & Direct Generation (P0)
- Expand `MuleRouterProvider.SupportedModels()` with full catalog (25+ models)
- Add category tags to `MediaModelInfo`
- Implement `POST /api/media/generate` with SSE streaming
- Session injection of generated media as chat messages

### Phase 3: Frontend Parameter Panel (P0)
- `MediaParamPanel.vue` — model selector, category-specific params
- Integrate into `ChatInput.vue` send flow
- "Switch to Chat" escape hatch
- Model memory (localStorage last-used per category)

### Phase 4: Placeholder & Progress (P1)
- `MediaPlaceholder.vue` — pending/progress/complete/failed states
- SSE-driven progress updates
- Cancel button with retry/fallback options
- Smooth transitions between states

### Phase 5: Polish & Edge Cases (P1)
- Ambiguity resolution UI (when classifier is unsure)
- Multi-image input handling (kf2v with 2 frames)
- Error recovery and retry logic
- i18n for parameter labels and status messages (all 27 locales)
- Accessibility: keyboard navigation, screen reader support

## 9. API Reference (MuleRouter)

Base URL: `https://api.mulerouter.ai`

### 9.1 Endpoint Pattern

**Generation (async):**
```
POST /vendors/{vendor}/v1/{model}/generation
Authorization: Bearer {api_key}
Content-Type: application/json
```

**Task Polling:**
```
GET /vendors/{vendor}/v1/{model}/generation/{task_id}
Authorization: Bearer {api_key}
```

### 9.2 Vendor Mapping

| Vendor | Models |
|--------|--------|
| `openai` | dall-e-3 (sync, uses `/v1/images/generations`) |
| `alibaba` | qwen-*, wan2.2-*, wan2.5-*, wan2.6-* |
| `google` | nano-banana-pro |
| `midjourney` | midjourney (`/tob/diffusion`), midjourney-video (`/tob/video-diffusion`) |
| `mulerouter` | wan2.5-*-spark, wan2.6-*-spark |

### 9.3 Common Request Fields

| Field | Type | Description |
|-------|------|-------------|
| `prompt` | string | Generation prompt (max 2000 chars) |
| `negative_prompt` | string? | Unwanted content |
| `image` | string? | Reference image (URL or base64) |
| `size` | string? | Output size (e.g., "1024x1024") |
| `resolution` | string? | "720P" or "1080P" (video) |
| `duration` | int? | Video length in seconds (5 or 10) |
| `audio` | bool? | Auto-generate audio (default true) |
| `audio_url` | string? | Custom audio file URL |
| `prompt_extend` | bool? | Intelligent prompt rewriting (default true) |
| `seed` | int? | Random seed (0-2147483647) |
| `n` | int? | Number of outputs |

### 9.4 Response Format

**Creation (202 Accepted):**
```json
{
  "task_info": {
    "id": "uuid",
    "status": "pending",
    "created_at": "ISO-8601",
    "updated_at": "ISO-8601"
  }
}
```

**Polling (200 OK — in progress):**
```json
{
  "task_info": { "id": "uuid", "status": "processing" },
  "progress": 0.45
}
```

**Polling (200 OK — complete):**
```json
{
  "task_info": { "id": "uuid", "status": "succeeded" },
  "output": {
    "results": [
      { "url": "https://...", "type": "image" }
```

## 11. Open Questions

1. **Should the IR classifier also run server-side?** Client-side gives instant feedback, but server-side ensures consistency. Current plan: both, with client-side as primary.
2. **How to handle prompt enhancement?** MuleRouter's `prompt_extend` does this, but should we also offer a "enhance prompt" button that uses the LLM?
3. **Model pricing display?** MuleRouter has per-model pricing — should we show estimated cost before generation?
4. **Batch generation?** Should users be able to queue multiple generations with different params?
5. **History/gallery view?** Should there be a dedicated page for all generated media (beyond chat history)?
