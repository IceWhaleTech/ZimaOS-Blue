# v0.10.30 Voice Input Enhancement — PRD

**Version**: 0.10.30
**Created**: 2026-02-25

---

## Overview

Overhaul the voice input experience across mobile and desktop to feel responsive, intuitive, and modern. Inspired by WeChat's latest voice UX patterns. Six areas of improvement targeting ChatInput (hold-to-speak), inline mic STT, TalkMode (voice call), and settings cleanup.

---

## 1. Hold-to-Speak Button — Reduce Latency & Improve Feel

**Current state**: `ChatInput.vue` uses a 150ms `setTimeout` delay before `startRecording()` on `touchstart`. The button feels "hard" and unresponsive on mobile.

**Target files**: [ChatInput.vue](web/src/components/ChatInput.vue)

### Requirements

- Remove or reduce the 150ms `longPressTimer` delay. Start recording immediately on `touchstart` (0ms or at most 50ms debounce to filter accidental taps).
- Add haptic feedback via `navigator.vibrate(10)` on recording start (where supported).
- Add a visual "breathing" animation on the hold-to-speak button during recording — replace the current `animate-pulse` with a smoother scale + glow keyframe.
- Show a waveform/audio-level indicator while recording (use existing `AudioRecorder` level data).
- Ensure `touchmove` beyond a threshold (e.g. 50px vertical) cancels recording without sending — show "slide up to cancel" hint.

## 2. Swipe-to-Choose: Send Voice vs. Transcribe to Text

**Current state**: On touch release, audio is always sent to ASR for transcription, then the text is placed in the input (or sent directly depending on `editBeforeSend` setting). No option to send raw voice.

**Target files**: [ChatInput.vue](web/src/components/ChatInput.vue), [en-US.ts](web/src/i18n/locales/en-US.ts), [zh-CN.ts](web/src/i18n/locales/zh-CN.ts)

### Requirements

- On `touchend`, show a brief inline selector (slide-up sheet or horizontal swipe targets):
  - **Left swipe / default release**: Send voice message directly (walkie-talkie mode — default behavior).
  - **Right swipe**: Transcribe to text first, then place in input for editing/sending.
- Default behavior (simple release without swipe) = send voice directly. This is the "walkie-talkie default" — fastest path.
- Remove the `editBeforeSend` setting from SpeechSettings since the swipe gesture replaces it. Keep the prop on TalkMode for backward compat but default to `false`.
- Add visual affordance: while holding, show subtle left/right arrows with labels "Send voice" / "To text".
- If the user swipes up (cancel gesture from item 1), neither action fires.

### Settings cleanup

- Remove or deprecate `editBeforeSend` / `editBeforeSendDesc` from i18n and SpeechSettings UI.
- The setting can remain in the API/store for backward compat but should no longer be shown.

## 3. Inline Mic Icon — Tap-to-Dictate with VAD

**Current state**: No inline mic icon in the text input area. Voice input requires switching to voice mode (compact) or opening TalkMode.

**Target files**: [ChatInput.vue](web/src/components/ChatInput.vue)

### Requirements

- Add a small microphone icon (🎙️ style) inside the text input area, right-aligned, visible when the input is empty or has text (always visible on both mobile and desktop).
- Tap the icon to start VAD-based speech-to-text:
  - Begin listening immediately.
  - Show a green backlight/glow animation on the mic icon while actively listening.
  - Use VAD (Voice Activity Detection) to auto-detect when the user stops speaking.
  - On silence detection, automatically stop recording, transcribe, and insert text at cursor position.
  - Return to normal (no glow) mic icon state after transcription completes.
- This is similar to WeChat's latest inline dictation feature.
- The icon should not conflict with the existing clear (X) button — place mic to the left of the clear button, or show mic when input is empty and clear button when input has text.
- On desktop (non-touch), clicking the mic icon works the same way — click to start, VAD auto-stops, or click again to stop manually.
- Green glow spec: `box-shadow: 0 0 8px rgba(34, 197, 94, 0.6)` with a subtle pulse animation, applied to the icon container.

## 7. VAD Implementation — Zero-Dependency Energy-Based Detection

**Context**: Items 3 (inline mic) and 4 (conversation mode) both require VAD to auto-detect when the user stops speaking. This section specifies the shared VAD engine.

### Why NOT `@ricky0123/vad-web` + Silero ONNX

- `onnxruntime-web` WASM: ~3-4MB
- `silero_vad_v5.onnx` model: ~2MB
- `@ricky0123/vad-web` package: ~150KB gzip
- **Total: ~6MB lazy-loaded** — too heavy for a VAD feature that just needs to detect "user stopped talking"
- Adds `onnxruntime-web` as a dependency (WASM files need to be served from `public/`, complicates build)
- Silero's strength is noise-robust speech/non-speech classification — overkill when we already have a quiet mic input and just need silence detection

### Chosen approach: Web Audio API energy-based VAD

Zero dependencies. Uses `AudioContext` + `AnalyserNode` + `ScriptProcessorNode`/`AudioWorklet` already available in all modern browsers.

**Target file**: `web/src/utils/vad.ts` (new)

### Algorithm

```
1. getUserMedia({ audio: true }) → MediaStream
2. AudioContext.createMediaStreamSource(stream)
3. Connect to AnalyserNode (fftSize: 2048, smoothingTimeConstant: 0.3)
4. Every frame (~60fps via requestAnimationFrame or 50ms setInterval):
   a. getByteTimeDomainData(dataArray)
   b. Compute RMS = sqrt(mean(samples²))  — normalize to 0-1 range
   c. Compare RMS against speechThreshold (default: 0.015)
5. State machine:
   - IDLE → SPEAKING: RMS > speechThreshold for >= minSpeechFrames (3 frames, ~150ms)
   - SPEAKING → SILENCE_PENDING: RMS < silenceThreshold for 1 frame
   - SILENCE_PENDING → IDLE: RMS < silenceThreshold for >= silenceDuration (default: 1500ms)
   - SILENCE_PENDING → SPEAKING: RMS > speechThreshold (user resumed talking)
6. On SPEAKING → IDLE transition: fire onSpeechEnd(audioBlob)
```

### API Design

```typescript
interface VADOptions {
  /** RMS threshold to consider as speech (0-1). Default: 0.015 */
  speechThreshold?: number
  /** RMS threshold to consider as silence (0-1). Default: 0.01 */
  silenceThreshold?: number
  /** Duration of silence before triggering speech end (ms). Default: 1500 */
  silenceDuration?: number
  /** Minimum speech duration to be considered valid (ms). Default: 300 */
  minSpeechDuration?: number
  /** Called when speech starts */
  onSpeechStart?: () => void
  /** Called when speech ends, with the recorded audio segment */
  onSpeechEnd?: (audio: Blob) => void
  /** Called with current RMS level (0-1) for visualization. ~20fps */
  onVolumeChange?: (level: number) => void
}

class EnergyVAD {
  constructor(options?: VADOptions)
  /** Start listening. Requests mic permission if needed. */
  async start(): Promise<void>
  /** Stop listening and release mic. */
  stop(): void
  /** Pause VAD detection without releasing mic (for TTS playback). */
  pause(): void
  /** Resume VAD detection after pause. */
  resume(): void
  /** Whether currently listening. */
  readonly isListening: boolean
  /** Whether speech is currently detected. */
  readonly isSpeaking: boolean
  /** Destroy and release all resources. */
  destroy(): void
}
```

### Audio Capture During VAD

The VAD needs to capture audio while detecting speech, so we can send it to ASR when speech ends:

- Use `MediaRecorder` alongside the `AnalyserNode` — both connected to the same `MediaStream`
- On `onSpeechStart`: call `mediaRecorder.start(100)` to begin collecting chunks
- On `onSpeechEnd`: call `mediaRecorder.stop()`, collect chunks into Blob, convert to WAV via existing `convertToWav()`, pass to callback
- This reuses the existing `AudioRecorder` pattern but driven by VAD state transitions instead of manual button presses

### Integration Points

**Item 3 (Inline mic)**: `ChatInput.vue`
```
tap mic icon → new EnergyVAD({ onSpeechEnd: transcribeAndInsert }) → start()
→ VAD detects silence → onSpeechEnd(blob) → convertToWav → speechApi.transcribe → insert text
→ vad.stop()
```

**Item 4 (TalkMode conversation)**: `TalkMode.vue`
```
open talk mode → new EnergyVAD({ onSpeechEnd: transcribeAndSend, silenceDuration: 1500 }) → start()
→ VAD detects silence → onSpeechEnd(blob) → convertToWav → speechApi.transcribe → send to chat
→ LLM streaming response → StreamingTTSManager plays audio
→ vad.pause() during TTS playback (prevent echo/feedback)
→ TTS complete → vad.resume() → next turn
```

### Interruption (Barge-in)

When TTS is playing and the user starts speaking:
- Keep VAD active (don't pause) but with a higher `speechThreshold` (0.03) during TTS playback to avoid echo triggering
- On `onSpeechStart` during TTS: immediately call `streamingTTSManager.stop()` + `ttsAudioManager.stop()`
- Transition to new listening round

Alternative (simpler, recommended for v1): pause VAD during TTS, resume after. No barge-in in v1 — user waits for AI to finish. Add barge-in in v2 with echo cancellation.

### Audio Level Visualization Fix

Current `startAudioLevelMonitor()` in TalkMode.vue uses `Math.random()` — replace with real data from `EnergyVAD.onVolumeChange`:

```typescript
const vad = new EnergyVAD({
  onVolumeChange: (level) => {
    audioLevel.value = level * 100  // normalize to 0-100 for existing UI
  }
})
```

### Tuning Parameters

| Parameter | Inline Mic (Item 3) | TalkMode (Item 4) |
|-----------|---------------------|---------------------|
| speechThreshold | 0.015 | 0.015 |
| silenceThreshold | 0.01 | 0.01 |
| silenceDuration | 1200ms | 1500ms |
| minSpeechDuration | 300ms | 500ms |

Inline mic uses shorter silence duration for snappier dictation. TalkMode uses longer to allow natural pauses in conversation.

### Limitations & Future

- Energy-based VAD can false-trigger on non-speech noise (typing, fan). Acceptable for v1 since the user explicitly activates listening.
- If accuracy becomes an issue, can upgrade to Silero VAD later — the `EnergyVAD` API is designed to be swappable (same interface).
- No echo cancellation in v1 — VAD pauses during TTS playback.

## 8. TalkMode Conversation Flow — End-to-End Pipeline

**Current state**: TalkMode's "conversation" mode has the WebSocket infrastructure but the actual flow is: manual button press → record → manual stop → transcribe → LLM → TTS. Not a continuous conversation.

**Target files**: [TalkMode.vue](web/src/components/chat/TalkMode.vue), [voice.ts](web/src/api/voice.ts), `web/src/utils/vad.ts` (new)

### New Conversation Loop

```
┌─────────────────────────────────────────────────────┐
│                    TALK MODE OPEN                     │
│                                                       │
│  ┌──────────┐    silence     ┌──────────────┐        │
│  │ LISTENING │──────────────→│ TRANSCRIBING  │        │
│  │ (VAD on)  │   detected    │ (Whisper ASR) │        │
│  └──────────┘                └──────┬───────┘        │
│       ↑                             │                 │
│       │                             ↓                 │
│       │                      ┌──────────────┐        │
│       │                      │  PROCESSING   │        │
│       │                      │ (LLM stream)  │        │
│       │                      └──────┬───────┘        │
│       │                             │                 │
│       │                             ↓                 │
│       │                      ┌──────────────┐        │
│       │    TTS complete      │   SPEAKING    │        │
│       └──────────────────────│ (stream TTS)  │        │
│                              └──────────────┘        │
│                                                       │
│              [tap button = stop/close]                │
└─────────────────────────────────────────────────────┘
```

### Key Changes from Current Implementation

1. **Replace `AudioRecorder` with `EnergyVAD`** in conversation mode — VAD manages mic and auto-detects speech boundaries
2. **Remove manual start/stop listening** — the loop is automatic after opening talk mode
3. **Use existing `StreamingTTSManager`** for TTS playback (already supports sentence-level streaming)
4. **VAD pause/resume** around TTS playback to prevent feedback
5. **The main button becomes a stop button** — tap to end the conversation session, not to toggle recording
6. **Remove WebSocket dependency for conversation flow** — use direct HTTP calls (speechApi.transcribe + chat SSE + TTS SSE) instead of the voice WebSocket. The WebSocket was designed for a server-driven flow that we're replacing with client-driven VAD.

### State Machine

```typescript
type ConversationState = 'listening' | 'transcribing' | 'processing' | 'speaking' | 'idle'
```

Transitions:
- `idle` → `listening`: Talk mode opened, VAD started
- `listening` → `transcribing`: VAD fires `onSpeechEnd`
- `transcribing` → `processing`: Transcript received, sending to chat
- `processing` → `speaking`: LLM response streaming, TTS playing
- `speaking` → `listening`: TTS complete, VAD resumed
- Any state → `idle`: User closes talk mode

### Error Recovery

- ASR failure → show error toast, resume VAD (back to `listening`)
- LLM failure → show error toast, resume VAD
- TTS failure → skip audio, resume VAD (conversation continues without voice)
- Mic permission denied → show error, close talk mode
