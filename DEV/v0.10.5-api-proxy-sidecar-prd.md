# v0.10.5 API Proxy Sidecar

## Overview

This PRD defines a **major architectural enhancement** for ZimaOS-Echo: a local API Proxy Sidecar that intercepts and manages all Claude Code CLI requests. This component serves as a unified gateway for LLM API traffic, providing high availability, session monitoring, prompt injection interception, usage statistics, and future-proof extensibility.

## Goals

1. **Unified API Gateway** - Single entry point for all CC CLI API requests
2. **High Availability** - Route selection, configuration switching, and failover handling
3. **Session Monitoring** - Track and monitor all active sessions
4. **Security Interception** - Detect and block prompt injection attacks
5. **Usage Statistics** - Comprehensive token consumption, latency, and performance metrics
6. **Data Masking** - Reserved capability for sensitive data redaction (future)
7. **Dynamic Configuration** - Hot-reload configuration without restart
8. **Simple Authentication** - Basic auth for proxy access control
9. **Connection Optimization** - Long-lived connections and connection pooling
10. **Model Compatibility** - Handle feature gaps in different models (e.g., tool calling)

## Non-Goals (This Version)

- Full data masking implementation (reserved interface only)
- Complex authentication (OAuth, OIDC)
- Multi-tenant isolation
- Distributed proxy cluster

## Target Users

- ZimaOS-Echo users who want centralized API management
- Developers who need detailed usage analytics
- Security-conscious users who want prompt injection protection
- Users with multiple LLM providers requiring unified access

## Core Features

### 1. Dynamic Port Binding

The proxy sidecar does NOT use a fixed port. Instead, it dynamically allocates an available port at startup.

```go
// ProxyConfig proxy configuration
type ProxyConfig struct {
    // Port configuration
    Port        int    `json:"port"`         // 0 = dynamic allocation
    PortRange   string `json:"port_range"`   // e.g., "9000-9100"
    BindAddress string `json:"bind_address"` // Default: "127.0.0.1"

    // Port discovery
    PortFile    string `json:"port_file"`    // Write allocated port to file
    EnvVar      string `json:"env_var"`      // Export port as environment variable
}

// GetProxyEndpoint returns the current proxy endpoint
func GetProxyEndpoint() string {
    // Read from port file or environment variable
    // Returns: "http://127.0.0.1:9042" (example)
}
```

**Port Discovery Methods:**

1. **Port File**: Write port to `~/.local/share/zimaos-echo/proxy.port`
2. **Environment Variable**: Export as `ECHO_PROXY_PORT`
3. **API Endpoint**: Query `/api/v1/proxy/status` for current port
4. **Unix Socket** (optional): Use Unix domain socket instead of TCP

### 4. Prompt Injection Interception

```go
// PromptGuard detects and blocks prompt injection attacks
type PromptGuard struct {
    Enabled     bool              `json:"enabled"`
    Mode        GuardMode         `json:"mode"`        // block, warn, log
    Rules       []InjectionRule   `json:"rules"`
    Whitelist   []string          `json:"whitelist"`   // Trusted patterns
    OnDetection func(alert *InjectionAlert)
}

type GuardMode string

const (
    GuardModeBlock GuardMode = "block"  // Block and return error
    GuardModeWarn  GuardMode = "warn"   // Allow but log warning
    GuardModeLog   GuardMode = "log"    // Log only, no action
)

// InjectionRule defines a detection rule
type InjectionRule struct {
    ID          string   `json:"id"`
    Name        string   `json:"name"`
    Description string   `json:"description"`
    Pattern     string   `json:"pattern"`      // Regex pattern
    Severity    string   `json:"severity"`     // low, medium, high, critical
    Action      string   `json:"action"`       // block, warn, log
    Enabled     bool     `json:"enabled"`
}

// InjectionAlert represents a detected injection attempt
type InjectionAlert struct {
    Timestamp   time.Time `json:"timestamp"`
    SessionID   string    `json:"session_id"`
    RuleID      string    `json:"rule_id"`
    RuleName    string    `json:"rule_name"`
    Severity    string    `json:"severity"`
    MatchedText string    `json:"matched_text"`
    Action      string    `json:"action_taken"`
    Blocked     bool      `json:"blocked"`
}
```

**Built-in Detection Rules:**

| Rule ID | Name | Pattern | Severity |
|---------|------|---------|----------|
| `INJ-001` | System Prompt Override | `ignore.*previous.*instructions` | Critical |
| `INJ-002` | Role Manipulation | `you are now.*|pretend to be` | High |
| `INJ-003` | Jailbreak Attempt | `DAN|do anything now|jailbreak` | Critical |
| `INJ-004` | Instruction Injection | `\[INST\]|\[/INST\]|<<SYS>>` | High |
| `INJ-005` | Delimiter Injection | `###.*instruction|---.*system` | Medium |
| `INJ-006` | Encoding Bypass | `base64.*decode|rot13|hex` | Medium |

### 12. Claude Code CLI Daemon Mode (Optional Enhancement)

If feasible, the CC CLI can run in daemon mode to reduce startup overhead:

```go
// DaemonConfig daemon mode configuration
type DaemonConfig struct {
    Enabled         bool          `json:"enabled"`
    SocketPath      string        `json:"socket_path"`      // Unix socket path
    IdleTimeout     time.Duration `json:"idle_timeout"`     // Auto-shutdown after idle
    MaxSessions     int           `json:"max_sessions"`     // Max concurrent sessions
    PrewarmSessions int           `json:"prewarm_sessions"` // Pre-warmed session count
}
```

**Benefits of Daemon Mode:**
- Reduced cold start latency
- Session reuse for faster subsequent requests
- Lower memory footprint (shared process)
- Better resource management

**Note:** This depends on CC CLI supporting daemon mode. If not available, the proxy will manage CLI process lifecycle directly.

## Security Considerations

1. **Local Binding Only** - By default, bind to `127.0.0.1` only
2. **API Key Protection** - Never log or expose API keys
3. **Prompt Injection** - Block known injection patterns
4. **Rate Limiting** - Prevent abuse with rate limits
5. **Auth Token Hashing** - Store tokens hashed, not plaintext
6. **TLS Verification** - Verify upstream TLS certificates
7. **Input Validation** - Validate all configuration inputs
8. **Audit Logging** - Log security-relevant events
