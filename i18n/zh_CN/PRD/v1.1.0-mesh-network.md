## 概览（Overview）

ZimaOS Echo 将支持 P2P 分布式 Mesh 网络，允许用户设备之间直接通信，并可选择性地加入中继网络为其他用户提供中继服务。  
该功能参考 [EasyTier](https://github.com/EasyTier/EasyTier) 的设计理念，实现去中心化的网络连接层。

## 目标（Goals）

- [ ] 实现设备间的 P2P 直连通信  
- [ ] 支持 NAT 穿透（STUN/TURN）  
- [ ] 提供可选的中继节点功能  
- [ ] 建立基于积分的激励机制，鼓励用户贡献带宽  
- [ ] 确保网络安全与隐私保护

## 用户故事（User Stories）

### 故事 1：P2P 直连

**作为一名** ZimaOS 用户  
**我希望** 能直接连接到我的其他设备  
**从而** 在不依赖中心服务器的情况下访问我的 NAS

**验收标准：**
- [ ] 支持通过 NAT 穿透自动建立 P2P 连接  
- [ ] 连接失败时自动回退到中继模式  
- [ ] 清晰显示当前连接类型（直连 / 中继）

### 故事 2：加入中继网络

**作为一名** 拥有良好网络条件的用户  
**我希望** 将我的设备作为中继节点  
**从而** 帮助其他用户并获得积分奖励

**验收标准：**
- [ ] 提供清晰的加入 / 退出中继网络选项  
- [ ] 显示资格检测结果（带宽、NAT 类型）  
- [ ] 实时展示中继流量与积分收益

### 故事 3：积分激励

**作为一名** 中继节点运营者  
**我希望** 查看我的积分余额和历史记录  
**从而** 了解自己贡献的价值

**验收标准：**
- [ ] 实时显示积分余额  
- [ ] 展示积分获取 / 消耗历史

## 技术设计（Technical Design）

### 架构（Architecture）

```text
┌─────────────────────────────────────────────────────────────────┐
│                      Discovery Server                            │
│       （节点发现、NAT 类型检测、中继分配）                        │
└─────────────────────────────────────────────────────────────────┘
                              │
          ┌───────────────────┼───────────────────┐
          │                   │                   │
          ▼                   ▼                   ▼
    ┌──────────┐        ┌──────────┐        ┌──────────┐
    │  Node A  │◀──────▶│  Node B  │◀──────▶│  Node C  │
    │ (Client) │  P2P   │ (Relay)  │  P2P   │ (Client) │
    └──────────┘        └──────────┘        └──────────┘
          │                   ▲                   │
          │                   │                   │
          └───────────────────┴───────────────────┘
                        Relay Fallback
```

### NAT 类型分类

| NAT Type | P2P 可行性 | 可作为中继 | 说明 |
|----------|-----------|-----------|------|
| Full Cone | 高 | ✅ | 最佳，任意外部主机可访问 |
| Restricted Cone | 高 | ✅ | 需要先发起连接 |
| Port Restricted Cone | 中 | ❌ | 需要精确端口匹配 |
| Symmetric | 低 | ❌ | 每次连接端口不同，难以穿透 |

### 中继节点准入条件

```yaml
relay_requirements:
  bandwidth:
    upload_min: 10    # Mbps
    download_min: 10  # Mbps
  nat_type:
    allowed:
      - full_cone
      - restricted_cone
    denied:
      - port_restricted_cone
      - symmetric
  uptime:
    min_hours_per_day: 8  # 建议值
  latency:
    max_to_discovery: 100  # ms
```

### 积分计算公式

```text
积分 = 中继流量(GB) × 基础系数 × 质量系数

质量系数 = f(带宽, 延迟, 可用性)
  - 带宽 > 100Mbps：×1.5
  - 延迟 < 20ms：×1.2
  - 可用性 > 99.9%：×1.3
```

### 协议选型（Protocol Choices）

| 协议 | 优点 | 缺点 | 选择 |
|------|------|------|------|
| WireGuard | 高性能、现代加密 | 需要内核支持 | ✅ 首选 |
| QUIC | 用户态实现、NAT 友好 | 相对较新 | 备选 |
| WebRTC | 浏览器友好 | 复杂度高 | Web 场景 |
