# ZimaOS Echo Ngrok 远程访问设计

**版本**: 1.0
**创建日期**: 2026-01-31
**性质**: 产品设计文档

---

## 1. 设计目标

### 1.1 核心理念

**"扫码即连，随时随地"**

- 用户通过手机扫码即可从外网访问家中的 ZimaOS Echo
- 零配置，无需了解端口转发、DDNS 等技术概念
- 解决 ngrok 免费版 8 小时会话限制的用户体验问题
- **ngrok 以插件方式下载**，类似 Claude Code CLI 的处理方式

### 1.2 关键价值

| 痛点 | 解决方案 |
|------|----------|
| 家庭网络无公网 IP | ngrok 隧道自动穿透 |
| 路由器端口转发复杂 | 一键启动，无需配置 |
| 动态 IP 地址变化 | 自动更新访问地址 |
| 8 小时会话过期 | 智能续期 + 邮件通知 |
| ngrok 二进制体积大 | 按需下载，不打包到主程序 |

## 2. 用户场景分析

### 2.1 目标用户

```
场景 A: 外出办公
- 用户在公司想访问家中的 AI 助手
- 需要快速获取访问地址
- 希望手机扫码直接打开

场景 B: 移动设备访问
- 用户在手机上想使用 Echo
- 家中 Echo 运行在内网
- 需要简单的连接方式

场景 C: 分享给家人
- 用户想让家人也能访问
- 不想教复杂的网络配置
- 希望分享一个链接即可
```

### 2.2 使用频率预估

| 场景 | 频率 | 优先级 |
|------|------|--------|
| 外出临时访问 | 每周 2-3 次 | 高 |
| 长期远程使用 | 每天 | 中 |
| 分享给他人 | 偶尔 | 低 |

## 3. Ngrok 8 小时限制解决方案

### 3.1 问题分析

ngrok 免费版限制：
- 单次会话最长 8 小时
- 会话过期后 URL 失效
- 需要重新启动获取新 URL

### 3.2 解决方案对比

| 方案 | 优点 | 缺点 | 推荐度 |
|------|------|------|--------|
| **A. 自动续期** | 用户无感知 | 需要定时任务 | ★★★★★ |
| **B. 邮件通知** | 用户知情 | 需要手动操作 | ★★★★☆ |
| **C. 短链接服务** | URL 不变 | 需要额外服务 | ★★★☆☆ |
| **D. 付费升级** | 彻底解决 | 增加成本 | ★★☆☆☆ |

### 3.3 推荐方案：自动续期 + 邮件通知

```
┌─────────────────────────────────────────────────────────────┐
│                    自动续期机制                              │
├─────────────────────────────────────────────────────────────┤
│                                                             │
│  ngrok 会话启动                                              │
│       ↓                                                     │
│  记录启动时间 + URL                                          │
│       ↓                                                     │
│  定时检查（每 30 分钟）                                       │
│       ↓                                                     │
│  ┌─────────────────────────────────────────────────────┐   │
│  │ 距离过期 < 1 小时?                                   │   │
│  │     ↓ Yes                                           │   │
│  │ 1. 启动新 ngrok 会话                                 │   │
│  │ 2. 获取新 URL                                        │   │
│  │ 3. 关闭旧会话                                        │   │
│  │ 4. 发送邮件通知（如果配置了邮箱）                     │   │
│  │ 5. 更新二维码                                        │   │
│  └─────────────────────────────────────────────────────┘   │
│                                                             │
└─────────────────────────────────────────────────────────────┘
```

### 3.4 邮件通知设计

#### 3.4.1 通知时机

| 事件 | 通知内容 | 是否必须 |

### 5.2 Ngrok 插件下载机制

#### 5.2.1 设计原则

参考 Claude Code CLI 的下载机制，ngrok 作为插件按需下载：

- **不打包到主程序**：减少主程序体积
- **首次使用时下载**：用户启用远程访问时触发下载
- **支持断点续传**：大文件下载更可靠
- **版本管理**：支持检查更新和自动更新
- **多平台支持**：自动检测平台下载对应版本

#### 5.2.2 下载流程

```
用户点击"启用远程访问"
        ↓
检查 ngrok 是否已安装
        ↓
    ┌───┴───┐
    │       │
  已安装   未安装
    │       │
    ↓       ↓
  启动隧道  显示下载提示
            │
            ↓
        用户确认下载
            │
            ↓
        显示下载进度
            │
            ↓
        下载完成

```

| **ngrok CLI (插件下载)** | 官方支持，稳定，体积独立 | 需要下载 | ★★★★★ |

func StartTunnel(ctx context.Context, port int, authtoken string) (*Tunnel, error) {
    ngrokPath := GetNgrokPath()

        return nil, ErrNgrokNotInstalled
    }

    // 启动 ngrok 进程
    cmd := exec.CommandContext(ctx, ngrokPath, "http",
        "--authtoken", authtoken,
        "--log", "stdout",
        "--log-format", "json",
        fmt.Sprintf("%d", port),
    )

}

### 5.3 数据模型

```sql
-- 远程访问配置表
CREATE TABLE IF NOT EXISTS remote_access_config (
    id TEXT PRIMARY KEY DEFAULT 'default',
    enabled BOOLEAN DEFAULT FALSE,
    ngrok_authtoken TEXT,
    notification_email TEXT,
    notify_on_update BOOLEAN DEFAULT TRUE,
    notify_on_expiry BOOLEAN DEFAULT FALSE,
    notify_on_error BOOLEAN DEFAULT TRUE,
    created_at DATETIME DEFAULT CURRENT_TIMESTAMP,
    updated_at DATETIME DEFAULT CURRENT_TIMESTAMP
);

-- 远程访问会话表
CREATE TABLE IF NOT EXISTS remote_access_sessions (
    id TEXT PRIMARY KEY,
    tunnel_url TEXT NOT NULL,
    started_at DATETIME NOT NULL,
    expires_at DATETIME NOT NULL,
    renewed_count INTEGER DEFAULT 0,
    status TEXT DEFAULT 'active',  -- active, expired, error
    error_message TEXT,
    created_at DATETIME DEFAULT CURRENT_TIMESTAMP
);

-- 远程访问日志表
CREATE TABLE IF NOT EXISTS remote_access_logs (
    id TEXT PRIMARY KEY,
    session_id TEXT,
    event_type TEXT NOT NULL,  -- started, renewed, expired, error
    message TEXT,
    metadata TEXT,  -- JSON
    created_at DATETIME DEFAULT CURRENT_TIMESTAMP
);
```
