# 管理与运维

Blue 现在的运维能力已经分散到多张真实页面里，而不是藏在一个单独的后台面板。最实用的使用方式，是先知道“什么问题该去哪个页面”。

## 先看哪一页？

| 如果你要回答... | 打开 |
| --- | --- |
| “当前运行时健康吗？” | `首页` |
| “我应该检查哪些安全控制或暴露面？” | `安全` |
| “到底发生了什么、是谁做的？” | `审计` |
| “哪个提供方或模型正在拉高成本？” | `计费` |
| “怎么创建或管理工作区？” | `工作区` |
| “怎么管理某个工作区的成员或限额？” | `工作区详情` |
| “用户怎么登录？” | `登录提供方` 与 [身份与访问](/guides/identity-access) |
| “用户和权限怎么管理？” | `用户` 以及个人资料 / 认证相关流程 |

## 首页：先看运行时健康

`首页` 现在承担了轻量运维仪表盘的角色，当前实现可以展示：

- 系统状态
- Uptime
- CPU、内存、goroutine 卡片
- 可刷新的运行时指标历史
- 可选的 OS、硬件、运行时、磁盘、GPU、网络详情

如果你想先判断 Blue 本身是不是健康，这里通常是第一站，而不是一上来就钻到更深层设置里。

## 安全：真正做安全加固的地方

当前 `安全` 视图分成四个标签页：

- `总览`
- `安全控制`
- `监控`
- `日志`

这些 tab 合起来覆盖：

- 活跃会话与撤销
- 威胁统计与最近威胁事件
- 安全扫描、修复预览与修复执行
- Prompt firewall
- CORS、TLS、ACME 状态
- Sandbox 运行时信息与网络开关
- 工具审批策略
- 已批准目录与已批准浏览器站点
- Directory whitelist 行为

当你要做上线前加固、收紧 sandbox 或 approval 策略、检查部署是否比预期更开放时，就应该来这页。

## 审计：回答“发生了什么”

如果你要看的是事件历史，而不是当前状态，应该去 `审计`。当前它支持：

- 过滤审计记录
- 查看状态与动作拆分
- 按时间窗口过滤
- 导出 JSON 或 CSV

所以它适合做事故回看、改动追踪和复盘取证。

## 计费：不仅是总量，而是使用分析

当前 `计费` 更像模型使用可观测性页面，支持：

- 日期范围过滤
- 提供方和模型过滤
- `group_by` 视图，例如按天、provider、model
- 成功率汇总
- Token 与成本趋势图
- 明细视图
- CSV 导出
- 使用峰值异常的 drilldown

也就是说，下面这些问题都应该来 `计费` 找答案：

- 哪个提供方正在变贵？
- 哪个模型请求量最高？
- 某一天是不是出现了使用峰值？
- 成本上涨是某个提供方、某个模型，还是整体流量变化导致的？

## 工作区：工作区生命周期入口

`工作区` 页是工作区治理的起点。当前页面支持：

- 创建工作区
- 编辑工作区
- 选择工作区
- 直接进入“管理”
- 在权限允许时删除工作区
- 查看状态、slug、描述和创建时间

当你要给新团队开空间、隔离环境，或清理旧工作区时，就从这里开始。

## 工作区详情：真正做工作区管理的地方

进入某个具体工作区后，当前 `工作区详情` 被拆成四个标签页：

- `成员`
- `邀请`
- `设置`
- `限额`，仅所有者可见

这些 tab 可以处理：

- 成员角色调整
- 邀请与撤销
- 默认工作区语言
- 工作区时区
- 所有者可见的用户上限、存储上限、API 请求上限、工作流上限、渠道上限等限额

可以把 `工作区` 理解成“找到工作区”，把 `工作区详情` 理解成“真正管理工作区”。

## 登录提供方与用户：身份上线层

Blue 的身份相关页面已经足够独立，应该把它当成单独的运维层来看。当前产品包括：

- OIDC 风格和常见托管身份提供方的认证配置
- 基于 callback 的登录流程
- Preview bootstrap 与首个管理员创建流程
- 用户管理中的锁定、解锁、重置密码与权限操作
- 个人资料页级别的已绑定账号、API Key、MFA、WebAuthn

如果真正的问题是“谁能进系统、怎么进、权限怎么发”，就继续读 [身份与访问](/guides/identity-access)。

## 一个实用的 day-two 运维顺序

1. 先看 `首页`，确认运行时健康。
2. 在大规模开放前检查 `安全`。
3. 用 `审计` 确认关键动作都能追踪。
4. 真实流量开始后持续看 `计费`。
5. 涉及多个团队或空间时，再配置 `工作区` 与 `工作区详情`。
6. 在更广泛 onboarding 前，完成 `登录提供方`、`用户` 和身份策略。

## 常见页面走错方向的情况

- 在 `计费` 里找事故历史，而这其实该去 `审计`
- 把 `工作区` 当成完整工作区管理页，而没有继续进入 `工作区详情`
- 登录问题先去看一般安全配置，却没先检查 auth-provider 配置
- 运行时本身还不健康，就直接钻进更深设置页
