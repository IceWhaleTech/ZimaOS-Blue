# 产品总览

ZimaOS Blue 是一套面向自托管场景的开源、可审计运行时，用来构建和运营本地优先 AI 代理。

![Design principles](/design_principle.png)

## 产品定位

- **本地优先**：运行在你自己的硬件、网络与权限边界里
- **轻量可部署**：Go 运行时，强调低占用与长期运行
- **跨设备**：可覆盖桌面、服务器、NAS、边缘设备与 Raspberry Pi 类场景
- **可组合**：聊天、语音、自动化、知识、评测与工具能力能接在同一运行时之上

## 团队通常怎么用它

Blue 当前更像一套“可落地的运行时底座”，而不是单纯的模型壳。常见用法包括：

- 搭一个私有聊天与语音助手
- 把同一套运行时接到渠道、浏览器任务和自动化触发器上
- 在云模型、本地小模型与外部 agent 之间做统一路由
- 用评测体系评估 prompt、技能和工作流，再决定是否切换版本
- 把安全、身份、审计、计费和租户治理保留在同一套控制面里

## Blue 包含什么

- 负责运行时编排的 gateway 与 server 层
- 提供方池、模型路由和外部 agent 连接能力
- 上下文、记忆、工具、人格与执行层
- 渠道接入与远程交互能力
- 安全、认证、沙箱、审计、计费与租户控制
- 语音、浏览器、工作流、表单填充与自动化能力
- 评测、进化、评分、基线对比与技能迭代能力
- 技能、技能商店和工具目录等扩展面

## 生态接入面

![Channel, provider, and IDE ecosystem](/providers.png)

它的开放性主要体现在边界层：

- 渠道和社交平台可以接到同一个运行时核心
- Provider 可以自由组合，而不是被单一厂商锁定
- Coding IDE 与外部 agent 可以成为一等参与者
- 本地模型与云模型可以在同一个产品面里协作

## 整个产品里保持一致的东西

无论你在聊天、语音、渠道、自动化还是评测面里切换，几件事是共用的：

- 同一套 Provider 路由和模型选择层
- 同一套安全、权限与审计边界
- 同一套工具、记忆与运行时核心
- 同一套操作面，用于配置、可观测与治理
