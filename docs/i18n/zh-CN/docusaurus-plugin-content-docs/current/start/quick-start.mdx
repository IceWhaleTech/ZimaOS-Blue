# 快速开始

这一页是从“已经装好”到“已经有一个可用 Blue 实例”的最短实操路径。默认你已经完成安装，并按 [首次运行](/start/first-run) 跑通过一次基础启动检查。

![快速上手演示](/demo%20quickv4.gif)

## 前 15 分钟应该完成什么

- 本地已经能打开 Blue
- 你知道当前实例是在预览模式还是正常模式
- 至少接入了一个可用提供方
- 第一条聊天响应成功返回
- 你知道后续该去看提供方、身份、渠道、自动化还是评测文档

## 1. 先确认自己是怎么启动 Blue 的

选择与你当前安装方式一致的一条：

- 桌面应用：直接打开应用，再继续看 Web 界面
- 源码、偏生产方式：运行 `sh build.sh`
- 源码、偏开发方式：运行 `./build.sh start`

如果你已经不确定自己到底走的是哪条路径，先回看 [安装方式](/start/installation) 和 [首次运行](/start/first-run)，不要一开始就把问题归到提供方或账号配置上。

## 2. 完成最小运维配置

打开 Web 界面后，按这条最短路径走：

1. 如果实例还在预览模式，可以先体验一下，再在需要时通过升级流程创建首个管理员账号。
2. 打开 `设置 -> 模型`。
3. 添加一个你真正准备使用的提供方。
4. 选择默认提供方；如果需要更严格的路由，再检查允许模型。
5. 回到聊天页做一次冒烟测试。

点击 `Add provider` 前，建议先准备这些最小信息：

| 字段 | 为什么需要它 |
| --- | --- |
| 提供方名称 | 方便后续排查和识别 |
| 基础 URL 或端点 | 告诉 Blue 请求发往哪里 |
| API Key 或 bearer token | 完成提供方认证 |
| 兼容格式 | 让 Blue 说对协议，例如 `openai`、`responses`、`anthropic`、`google` |
| 云端或本地标记 | 方便判断部署形态 |
| 允许模型 | 需要收紧路由时直接可用 |

## 3. 先跑一次冒烟测试

先发一条简单 prompt，例如：

`Summarize what ZimaOS Blue is in one paragraph.`

一个健康的首轮结果通常意味着：

- 页面能正常打开
- 预览访问或正常登录都工作正常
- 提供方能成功返回结果
- 第一条响应已经回来
- 你已经知道下一步应该看哪一篇，而不是盲猜

## 4. 认识产品的三个核心层

- **运行时**：Blue 是轻量级、可部署的 Go 运行时
- **路由层**：模型与提供方通过配置完成选择、故障转移与回退
- **交互面**：用户通过聊天、语音、自动化和 Web 界面与系统交互
