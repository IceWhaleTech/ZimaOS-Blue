# Quick Start

This page is the shortest practical path from installation to a first usable Blue setup. It assumes Blue is already installed and that you have completed the startup checks in [First Run](/start/first-run).

![Quick product walkthrough](/demo%20quickv4.gif)

## What you should finish in the first 15 minutes

- Blue opens locally and you know which launch path you used
- You understand whether the instance is in preview mode or normal mode
- One provider is connected and configured correctly enough for a real reply
- One chat response succeeds
- You know which page to open next for providers, identity, channels, automation, or evaluation

## 1. Reconfirm how you are launching Blue

Choose the path that matches what you already installed:

- Desktop app: open the app, then continue in the web UI
- Source, production-style: run `sh build.sh`
- Source, development-style: run `./build.sh start`

If you are not sure which path you used, go back to [Installation](/start/installation) and [First Run](/start/first-run) before you keep debugging downstream issues.

## 2. Finish the minimum operator setup

Open the web UI and complete this short path:

1. If the instance is still in preview mode, explore briefly and then use the upgrade flow when you are ready to create the first admin account.
2. Open `Settings -> LLM`.
3. Add one provider you actually plan to use.
4. Pick the default provider and review allowed models if you want tighter routing.
5. Return to chat for a smoke test.

Before you click `Add provider`, it helps to have these values ready:

| Field | Why it matters |
| --- | --- |
| Provider name | Makes later routing and debugging easier to read |
| Base URL or endpoint | Tells Blue where to send requests |
| API key or bearer token | Authenticates the provider |
| Compatibility format | Lets Blue speak the correct protocol, such as `openai`, `responses`, `anthropic`, or `google` |
| Cloud or local location | Helps you reason about deployment shape |
| Allowed models | Lets you keep routing bounded if needed |

## 3. Run a first smoke test

Send one simple prompt such as:

`Summarize what ZimaOS Blue is in one paragraph.`

A healthy first pass looks like this:

- The UI loads without confusion about the local address
- Preview access or normal sign-in works
- The provider is accepted and can answer
- The first response returns successfully
- You know which page owns the next setup question instead of guessing

## 4. Learn the three core ideas

- **Runtime**: Blue is a Go-based agent runtime designed to stay lightweight and deployable
- **Routing**: providers and models are selected through configurable routing and failover
- **Surfaces**: users interact through app UI, channels, voice, automation, and support pages
