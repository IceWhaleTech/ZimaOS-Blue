# Research Workflows

Blue now exposes one public research family entry across the composer, runtime, and public interfaces.

## One entry, four modes

In the composer, the separate `Research`, `Analysis Report`, `Advisor`, and `UI Review` chips are replaced by one `Research` chip.

That single entry routes into four internal modes:

- `deep_research`: citation-first, multi-source, longer-running research
- `analyze`: bounded synthesis from known URLs, search queries, or pasted text
- `advisor`: decision support for selection, migration, replacement, and best-practice questions
- `ui_review`: UI, UX, and accessibility review for a URL or image

The public entry is now `research`, not three separate discovery names.

## What `mode` means

Explicit calls should use:

```json
{
  "action": "run",
  "mode": "auto|deep_research|analyze|advisor|ui_review"
}
```

Use `mode=auto` when you want Blue to choose the best submode from the request itself.

## How auto routing works

Blue uses the current request shape and intent cues to pick a mode:

- Requests asking for citations, evidence, timelines, comparisons, or deeper investigation route to `deep_research`
- Requests asking for a report or bounded synthesis from supplied URLs, searches, or pasted text route to `analyze`
- Requests asking for a recommendation, tradeoff analysis, replacement choice, or best-practice memo route to `advisor`
- Requests asking for UI critique, screenshot review, design review, or accessibility checks route to `ui_review`

Blue also recognizes "recent community discussion" prompts such as `What are people saying in the last 30 days about ...`. Those requests still enter through the public `research` surface, but the runtime now attaches an internal recent multi-site retrieval profile and gathers dated signals across public web, Reddit, Hacker News, GitHub, Polymarket, X, TikTok, Instagram, and Bluesky. Known YouTube URLs can be added as enrichment when they are already present in the request.

The `Research` toggle in chat is therefore a research-family preference signal, not a promise that every request will become deep research.

## Mode-specific inputs

Each mode keeps its own input contract inside the shared `research` family.

### `deep_research`

Use it for open-ended research questions and evidence-heavy synthesis.

Typical fields:

- `query`
- `research_depth`
- `report_style`
- citation and evidence-oriented routing settings

### `analyze`

Use it when the scope is already bounded by known material.

Typical fields:

- `topic`
- `urls`
- `search_queries`
- `text`
- `output_mode`
- `report_style`

This is the right fit for turning a small source set into a summary, briefing, dashboard-style report, or artifact such as Markdown or a document generated by a follow-up write step.

### `advisor`

Use it when the task is to make a decision rather than simply gather or summarize information.

Typical fields:

- `question`
- `category`
- `decision_mode`
- `candidates`
- `context`
- `constraints`
- `grounding`
- `depth`
- `output`

### `ui_review`

Use it when the task is to judge an interface rather than research a topic.

Typical fields:

- `action`
- `url`
- `image`
- `device`
- `channel`
- `threshold`
- `format`
- `profile`

This mode focuses on visual quality, UX issues, and accessibility findings.

## Final results stay mode-specific

Blue uses one shared research-family runtime internally, but the final user-facing results still stay distinct:

- `deep_research` keeps the deep-research presentation
- `analyze` renders a dedicated analyze result card
- `advisor` renders a decision-support result
- `ui_review` keeps the UI review presentation

This is an architectural merge, not a flattened generic result card.

## Public interface guidance

When documenting or integrating against the current public surface:

- Use `research` as the canonical skill, CLI, or API entry
- Pass `mode` explicitly when you already know the intended submode
- Use `mode=auto` for chat-style routing
- Do not rely on `deep_research`, `analyze`, `advisor`, or `ui_reviewer` as primary public discovery names
