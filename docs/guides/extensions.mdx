# Extensions

Blue's extension surface has grown from a simple plugin idea into a broader workspace for skills, remote skill discovery, and reusable tools.

## Three extension lanes

The current extensions page is organized into three top-level tabs:

- `Skills`: local or installed skills already available in the runtime
- `Skill Store`: remote discovery, browsing, and install flow
- `Tools`: reusable tool surfaces exposed alongside skills

This lets operators manage what Blue can do, where those capabilities came from, and how safe they appear before installation.

## Local skills

Local skills are the capabilities already present on disk or installed into the runtime. The app can surface:

- Skill identity and version
- Description, category, and tags
- Built-in versus installed status
- Contract metadata for newer or legacy skill manifests

This is the right place to confirm what is already active before you start pulling in more sources.

## Remote skill store

The skill-store flow is designed for discovery and governance, not just search-and-click install. The current data model supports:

- Multiple skill sources
- Search, filter, and category browsing
- Curated ranking and trending-style signals
- Source import preview before adding a new remote source
- Remote versus local skill distinction

That matters if you want a controlled marketplace-like experience without hiding where a skill came from.

## Security and install metadata

One of the newer extension improvements is the amount of install metadata Blue can surface before you trust a skill. The current skill model can carry:

- Security badge and risk level
- Install type such as raw skill, repo, script package, binary package, or manual external setup
- Artifact kind such as open-source, mixed, closed binary, or unknown
- Vulnerability status and scanner evidence
- Signals for prompt injection, shell injection, or data exfiltration risk

This makes the extension page part catalog and part operator review surface.

## Installation paths

The current UI supports both URL-based and file-based install flows for skills. A successful install can also return contract details so you can review what landed instead of treating install as a black box.

## Where plugins fit

Blue still exposes plugin concepts and plugin-store APIs, but the main user-facing extension workflow now centers on:

- Skills as reusable capability packages
- Skill sources and remote catalogs
- Tool surfaces for direct operator use

If your team is deciding what to allow into a shared runtime, start here before enabling broad access.

## Recommended operator path

1. Review local skills already present
2. Search the skill store for the missing capability
3. Check source, install metadata, and security badge
4. Install by URL or file only after the contract and risk surface make sense
5. Revisit Harness or Evolution if the new capability needs tracked evaluation

## Optional Parallel web search

Use [Parallel Search MCP](https://docs.parallel.ai/integrations/mcp/search-mcp) for web search with focused excerpts and source URLs. Anonymous searches use Fast mode and need no account or API key. Enable the provider in your `config.yaml`, then restart Blue:

```yaml
tool_calling:
  web_search:
    provider: parallel
    providers: [parallel]
```

This selects Parallel for the existing web-query and research search paths. Blue continues to use its existing page readers when a workflow opens a result. The default provider list remains `duckduckgo,bing` until you change it. An explicit single-provider selection reports failures rather than selecting another provider; configure a provider list if you want fallback.

For higher service limits, set `tool_calling.web_search.provider_settings.parallel.api_key` to a Parallel API key. Only Parallel's provider-specific key is sent; generic search credentials and environment API keys are not forwarded. `provider_settings.parallel.base_url` can override the complete MCP endpoint; the default is `https://search.parallel.ai/mcp`. Set `provider_settings.parallel.enabled: false` to disable the provider, including per-call overrides. Existing tool permissions still apply.

Anonymous access has service limits. Parallel does not implement Blue's `region` or `safe_search` switches; select another provider when those filters are required.
