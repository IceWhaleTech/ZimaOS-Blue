# Automation

Blue is more than a chat surface. The repository and product UI already expose several automation-oriented entry points.

## Automation surfaces in the current product

- Cron jobs via the main automation route
- Workflow and webhook entry points
- Browser automation and redirect paths for older browser-oriented routes
- Auto-reply and channel-linked automation patterns
- Form-filling services for structured browser interactions
- Harness-backed tracked runs for repeatable experiments and evaluations

## When automation becomes valuable

- You want scheduled tasks instead of ad hoc prompting
- You want external systems to trigger agent behavior through webhooks
- You want browser or workflow steps wrapped inside the same runtime
- You want automation to inherit the same security, provider, and audit model as chat
- You want repeatable evals, scorecards, and reports instead of one-off manual checks

## Automation tabs in the web app

The web router currently groups several workflows under automation:

- Main automation and cron entry points
- Harness run groups and run-group detail pages
- Evolution pages for skill optimization and instruction review
- Redirects from older `cron`, `webhooks`, `workflows`, and browser automation routes into the current automation structure

## Tracked automation vs one-off execution

Use plain automation when you want a scheduled or trigger-driven workflow. Use Harness when you need:

- A reusable dataset or eval spec
- Scoring and pass thresholds
- Baselines and comparison reports
- Artifacts, traces, and reviewable evidence

Read [Harness and Evolution](/guides/harness-evolution) for that control plane.
