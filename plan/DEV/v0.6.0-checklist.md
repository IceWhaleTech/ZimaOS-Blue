# v0.6.0 Implementation Checklist

[中文版本](../../i18n/zh_CN/plan/DEV/v0.6.0-checklist.md)

This checklist tracks the implementation progress of v0.6.0 (Message Channels & More Integrations).

## Goal
Multi-channel message support - enable users to interact with the agent through various messaging platforms.

## Acceptance Criteria
- [x] Channel abstraction interface fully implemented
- [x] At least 3 messaging channels working
- [x] All channels support streaming responses
- [x] Channel configuration via config file
- [x] Unit tests for all channel implementations

## Configuration

### New Config Options
```yaml
# config.yaml additions for v0.6

# Channel configuration
channels:
  # Global settings
  enabled: true
  default_timeout_seconds: 30
  max_message_length: 4096

  # Telegram
  telegram:
    enabled: false
    bot_token: ""
    webhook_url: ""  # Optional, uses long polling if empty
    allowed_users: []  # Empty = allow all
    allowed_groups: []
    proxy: ""  # Optional HTTP proxy

  # Discord
  discord:
    enabled: false
    bot_token: ""
    application_id: ""
    allowed_guilds: []
    allowed_users: []

  # Slack
  slack:
    enabled: false
    bot_token: ""
    app_token: ""  # For Socket Mode
    signing_secret: ""
    allowed_channels: []
    allowed_users: []

  # WeChat Work
  wechat_work:
    enabled: false
    corp_id: ""
    agent_id: ""
    secret: ""
    token: ""
    encoding_aes_key: ""
    callback_url: ""

  # Feishu/Lark
  feishu:
    enabled: false
    app_id: ""
    app_secret: ""
    verification_token: ""
    encrypt_key: ""

  # Matrix
  matrix:
    enabled: false
    homeserver: ""
    user_id: ""
    access_token: ""
    device_id: ""
    allowed_rooms: []

  # iMessage (macOS only)
  imessage:
    enabled: false
    database_path: "~/Library/Messages/chat.db"
    poll_interval_ms: 1000
    allowed_numbers: []  # Empty = allow all
    allowed_emails: []

  # WhatsApp
  whatsapp:
    enabled: false
    phone_number: ""
    session_path: "./data/whatsapp"
    allowed_numbers: []  # Empty = allow all

  # Signal
  signal:
    enabled: false
    phone_number: ""
    config_path: "./data/signal"
    allowed_numbers: []  # Empty = allow all
```

## API Endpoints (New)

| Method | Path | Description |
|--------|------|-------------|
| GET | `/api/v1/channels` | List all channels |
| GET | `/api/v1/channels/:name` | Get channel info |
| POST | `/api/v1/channels/:name/start` | Start a channel |
| POST | `/api/v1/channels/:name/stop` | Stop a channel |
| GET | `/api/v1/channels/:name/status` | Get channel status |
| POST | `/api/v1/channels/:name/test` | Test channel connection |

## Priority Order

Recommended implementation order:

### Phase 1: Foundation
1. Channel abstraction interface (types.go)
2. Channel manager implementation
3. Configuration support

### Phase 2: Popular Channels
4. Telegram Bot (most common for personal use)
5. Discord Bot (popular for communities)

### Phase 3: Enterprise Channels
6. Slack (enterprise standard)
7. WeChat Work (China enterprise)
8. Feishu/Lark (China enterprise)

### Phase 4: Open Protocol
9. Matrix (open, federated)

### Phase 5: Consumer Messaging
10. WhatsApp (popular consumer messaging)
11. Signal (privacy-focused messaging)

### Phase 6: Polish
12. API endpoints for channel management
13. Documentation
14. Integration tests

## Security Considerations

1. **Token Storage**: All tokens should be stored securely (env vars or encrypted config)
2. **Access Control**: Implement allowlists for users/groups/channels
3. **Rate Limiting**: Prevent abuse through rate limiting
4. **Input Validation**: Sanitize all incoming messages
5. **Audit Logging**: Log all channel activities
